# Explicit real Reference journeys

`corpus.json` freezes synthetic input facts, questions, expected values, source requirements and acceptance
before candidate model calls. This is opt-in development validation through the production Runtime, SQLite,
ProjectScope/Memory authority, real local Git membership, original reference and file Tools, and real Provider.
It is not another product evaluation runner and must never run as part of pytest collection.

The core contains 14 journeys × 2 opaque-identity repeats per model; each configured model needs at least
26/28 evidence-supported task successes, with zero source-scope, replay or durable-invariant violations.
Two semantic paraphrase journeys are a separately reported lexical diagnostic; their failures stay visible
and must not be called semantic acceptance. C3 must reuse these questions and judgments.

Memory is seeded through explicit host declaration and exact approve/revoke/supersede operations. A second
Session or project must be genuinely created and bound through the same Store and real Git resolver.
History bootstrap turns must call the real Provider through Runtime; a scripted acknowledgement does not
count as a real end-to-end journey. Compaction preserves the actual source events and removes the values
from the visible summary. The stale-file journey requires an actual successful file read with a host Git
observation before the isolated fixture repository changes.

Format 2 questions expose explicit `answer_fields` descriptions, including quantity units and identifier
extraction rules, without showing expected values or prescribing Tool calls. Missing descriptions and key
mismatches fail before any model call. Format 1 omitted those rules; retain its original scores without
rescoring, and measure format 2 in new frozen complete grids for both the existing and candidate sources.
Decode strict JSON (an enclosing Markdown JSON fence is only presentation), compare the frozen values,
and independently prove evidence from actual Context blocks and successful Tool results. A normal file
question must still read the actual file. File reads are allowed for all cases so an artificial reference-only
Tool denial cannot be misreported as a Memory retrieval failure.

All fixture paths and Git commits belong to isolated temporary test repositories. Do not read credentials
except through the existing environment loader in the calling child process; never export headers, real keys,
or `.env` content. Source snapshots, manifests, events, SQLite, attempts and failures must be retained.

`journey_fixtures.py` owns only synthetic inputs and isolated repository assembly. `bootstrap.py` uses the
existing host authority and real Runtime turns to prepare the cases. `assessment.py` checks exact JSON,
source identities, active approvals and freshness; every required body must be in the final dispatched
reference and every file result must be visible in its actual Tool message. `run.py` freezes hashes and
policies before calls, exports all original streams and SQLite, and separates bootstrap usage from target
attempts. A missing usage record is never counted as zero-cost success. Failures retain their denominator.
`audit.py` independently reopens the original SQLite, compares exports, validates every Session and
request, checks actual policy and user input against the frozen corpus, and reads final answer/outcome
from original assistant/turn events. A copied fixture with a forged report response is rejected.

Run explicitly with `src` and `tests` on `PYTHONPATH`, using `python -m live_reference_journeys.run` and
required `--env-file`, `--model`, `--output`, `--corpus` and `--skill-corpus` arguments. Use an unused output
directory and the frozen input files. Optional `--cases` or `--repeats` always marks a diagnostic subset;
it cannot claim full acceptance. No test imports the CLI entry point to make a real Provider call.
