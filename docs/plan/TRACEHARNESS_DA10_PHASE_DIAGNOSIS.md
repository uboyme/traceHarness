# DA-10：阶段切换请求的受限归因实验

日期：2026-09-12。状态：12 次真实对照已结束，四条件均为 0/3 有效决定提案，无生产采用。前序：[DA-9](TRACEHARNESS_DA9_SCOUT_THEN_DECIDE.md)。结果：[记录 036](../deal/036-phase-transition-diagnosis.md)。

## 问题与范围

DA-9 三道题第一次进入独占决定时均未调用决定工具。原冻结请求已包含决定 system 指令和唯一工具；但历史中还包含前一步宿主追加的侦察 user 指令，最终参考包又重申完成原任务。这是可观察的指令生命周期与呈现问题，尚不能宣称它是全部失败的原因。

本阶段仅做请求级诊断，不恢复 DA-9，不增加 Product/Runtime 生产能力，不执行模型返回的工具，不创建助手、Workspace 或 Promotion，不修改原 Session。保留原始日志与请求摘要，诊断副本有独立身份，不能冒充原请求或新的 Product 验收成绩。

## 冻结设计

从 DA-9 三类场景各取第一次独占决定的 dispatch_request，固定四个条件，每条件每场景一次，合计最多 12 次真实调用：

| 条件 | 移除过期侦察 user 提示 | 末尾追加当前决定 system 指令 |
|---|---|---|
| original | 否 | 否 |
| drop-stale | 是 | 否 |
| phase-last | 否 | 是 |
| both | 是 | 是 |

移除项必须逐字匹配归档候选的 `_SCOUT_PROMPT`，且每份输入恰好一条；追加项逐字复用归档 `_DECISION_PROMPT`。不改提示措辞、题目、证据正文、工具 schema、temperature 或输出上限。全部 assistant/tool 配对、原始用户目标及最终参考包保留。phase-last 同时改变位置并重复现有指令，因此其结果只能支持“末尾重申”整体干预，不能分辨位置和重复次数的贡献。

使用现有授权连接加载器，固定原 provider/model，直连、单次请求、不重试，单请求 60 秒超时；网络失败或未知 usage 即停止，不补跑。每个请求在调用前落盘，结果和精确 usage 在返回后落盘；中断留下已发起未完成状态，不能重新使用目录重跑。没有完整任务、基线套件、语义裁判或 Docker 启动。

## 判读与停止

逐项检查：是否只调用唯一公开工具、JSON Schema 是否合法、local/separable 字段之间是否满足原合同。分别记录选择，不把结构合法解释为拆分正确，不把决定提案解释为实际委派。原始 0/3 首次决定作为历史事实单独列出；本轮 original 反映相同输入重调的自然波动。

先验证转换不改原输入、不破坏 tool 配对、不添加答案，反例必须拒绝缺失/歧义侦察提示、错误决定面、摘要不匹配。验证 Provider 失败与取消不重试、不吞掉错误。定向测试、相邻 Provider/Context 回归、compileall、collect-only、Ruff、diff 和文档检查之后才做真实调用。
