# ADR-0076：宿主声明的验证说明与执行事实

状态：接受。日期：2026-09-13。延续 ADR-0073 的原验证 owner 和输出隐私边界。

## 原因

记录 067 中，主方收到固定检查失败后寻找未保留的 stderr，没有定位到代码问题。只有退出码不足以定位内部断言；框架也不能根据退出码猜业务根因。用户要求通用事实边界，不能针对某道题增加特判。

## 决定

VerifierCommand 增加宿主声明的 public_requirement。None 表示没有公开说明；非空文本最多 1000 字符，拒绝控制字符。JSON 配置必须明确给出字符串或 null，Python API 未声明时保持私有。说明描述整个命令所检查的要求，不是模型生成的诊断，也不是失败原因的证明。

公开说明进入原命令和计划 digest；Promotion/VerificationPlan 协议切换为 3，拒绝旧 1/2。原账本 schema 不另建，旧记录不迁移、不删除、不自动改写。当前配置、夹具、活动 benchmark 与摘要绑定同步更新，历史实验材料保持原样，旧实验需使用其冻结代码核验。

可写完成反馈在原 verification/result 的 summary 中，将公开说明与原 command_id、命令 digest、执行引用、状态及退出码放在一起。反馈前核对完整计划、逐项命令身份、结果数量与摘要及总体判定，拒绝把另一个命令结果标成当前公开要求的结果。原候选前后观察继续限定结果适用的工作区快照。

反馈明确 diagnostic_scope=command-result-only、failure_cause=unknown、raw_output_availability=not-retained。启动失败、超时、输出超限不判断业务正确性；命令失败不定位其内部子断言。原始 stdout/stderr 仍只临时处理，不进 Event/CAS，执行引用不是可读取 stderr 的地址，不增加读取工具。

宿主可把需要独立定位的要求拆成多个原 VerifierCommand；框架不会解析测试源码、捕捉业务异常或自动拆分检查。公开文字由配置作者负责与检查对应，框架只能证明执行身份和结果，不能证明自然语言与测试语义完全等价。

## 边界

公开的是显式要求说明与执行状态，不是任意原始输出。若宿主未提供公开说明，模型只能依据已公开需求、源码及获准的自测调查，或如实报告无法定位。没有自动重试、第二事实源、新工具、权限扩展或自动 Promotion。固定检查、Review 与人工批准仍各自独立。
