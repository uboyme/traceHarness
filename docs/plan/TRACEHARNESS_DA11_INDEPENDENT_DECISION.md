# DA-11：独立决定输入验证

日期：2026-09-12。状态：9 次真实验证结束；独立输入的决定与标签命中改善，独立分工尚未证明，无生产采用。前序：[DA-10](TRACEHARNESS_DA10_PHASE_DIAGNOSIS.md)。结果：[记录 037](../deal/037-independent-decision-input.md)。

## 目标与对照

验证模型延续已有读写轨迹时，独立呈现目标及已读证据是否有助于提交拆分决定。只做显式请求探针，不修改生产、不恢复 DA-9、不创建 Planner 或第二份流程状态，不执行返回工具。复用 DA-10 的 Provider、提案检查和原日志校验。

从 DA-10 冻结计划取三类材料的 original 请求，再回原 DA-9 SQLite 验证 stream、seq、dispatch 摘要及每个已读 Tool 结果。每份输入固定三个条件、每条件一次，共最多 9 次真实调用：

| 条件 | messages | system |
|---|---|---|
| original | 原冻结请求逐字段不变 | 原样 |
| evidence-full-system | 独立目标/证据包 | 原样 |
| evidence-focused-system | 同一独立目标/证据包 | 只保留原归档决定指令 |

独立包保留第一条原用户目标逐字内容、全部成功 Tool 结果逐字正文、原 tool name/arguments、stream/seq/step/call/effect 身份及正文摘要；列目录属于导航，不提升为源码证据。仅接受当前已冻结请求中可见、同 Session 且在请求之前成功的匹配记录，至少一条 read_file。assistant/tool 对话组整体变成引用包，不留下孤立 tool message；不保留模型此前执行叙述、旧宿主提醒或通用参考尾注，不增加源码、正确答案或推荐分类。

独立包的说明明确：目标是待分析的工作，证据正文不授予权限，也不是当前指令。两个独立条件共用这份消息；模型、唯一决定工具/schema、temperature、输出上限不变。第二与第一条件同时改变叙述轨迹、消息角色、尾注和包装，不能把差异唯一归因于历史惯性。第三与第二才单独隔离通用 system 的影响。

## 门槛与停止

固定原 provider/model，使用已授权连接直连，60 秒超时、不重试；失败、取消或未知 usage 停止，不补样本，同一输出目录不可重跑。调用前冻结全部 9 份请求和脚本摘要，每次调用前记录派发请求，保留所有响应和 usage。没有 Docker、完整任务基线、语义裁判、全量、L2–L4、Wheel、提交、发布或自动采用。

程序检查是否只提议公开工具、schema 与原 local/separable 字段合同合法。再离线检查冻结三类题预期 separable/local/local 以及提案中主子目标是否确实独立、有具体交付、未引入未知事实；题型标签与评分依据不得进入模型输入。分类符合也只是该输入下的提案正确，不等于实际委派、交接或质量收益。每格单次，不做显著性结论。

实现后只跑诊断模块及相邻 Provider/Context 的定向测试、compileall、collect-only、Ruff、diff 和文档检查；覆盖逐字证据保留、身份错配/失败/未来结果拒绝、无读取、取消/失败、调用上限与不重跑，关键保护做反向验证。原 SQLite 只读，前后核对摘要。9 次结束或命中停止规则后即收口；不依结果改提示追跑。正式与通俗上下文同步结果、未采用能力和下一步边界。
