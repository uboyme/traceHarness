# 主动检索可靠性实验计划：目标、变量与边界

日期：2026-09-09。状态：**RE-0–RE-5 已收口：112 条真实目标旅程，无稳定收益候选；RE-5 无合格组合，96 条条件性留出验证未启动。未采用新生产策略，不提交或发布。**

本计划接续[主动检索执行计划](TRACEHARNESS_ACTIVE_RETRIEVAL_EXECUTION_PLAN.md)与[最终对照记录 007](../deal/007-active-retrieval-final-comparison.md)。RE 只表示这一轮实验，不是新版本或新的 Runtime 阶段。执行授权覆盖隔离实验、真实测试及必要验证，不自动授予提交或发布权限；候选只有满足本计划证据门槛才考虑采用。当前证据目录为 [reliability-01](../validation-data/active-retrieval/reliability-01/experiment.json)。

## 1. 实验要回答什么

目标是找出剩余失败中可由通用接口、导航和呈现改善的共性问题，确认实际收益及代价。优先保持当前按需检索行为：有证据即可答，有线索且缺证据可继续查，受阻或无有效线索时限定结论范围。

本轮不以冲到 66/72 为任务完成条件，不承诺消除模型语义误判；也不靠要求每道题搜索、遍历全部材料或统一回答“不知道”获得更好数字。

需要分别回答：

1. 区分机器字段与正文，能否减少把内容指纹、进程退出码当业务答案？
2. 让来源级搜索入口与逐条读取入口同样清楚，能否帮助发现未进入初始参考的 Memory？
3. 有界多关键词查询，是否能改善字面关键词选错后的查找，还是只增加搜索量？
4. 更明确地呈现实际读取和搜索范围，能否减少全局否定，同时保留直接回答和合理停止？

## 3. 不可突破的目标约束

| 边界 | 实验及最终候选必须遵守 |
|---|---|
| 唯一事实源 | EventStore / Effect / 原不可变内容继续拥有事实；Projection 解释状态，Reader 复核资格，Context 编排模型输入。实验报告不是业务事实源 |
| 身份与权限 | 每次沿原 Session、project binding、Memory active/批准、Skill selection/catalog/Lease 规则读取；搜索入口、计数、工具暴露都不授权 |
| 不泄露不可见范围 | 不先扫描别的项目、未批准提议、撤销事实或未选 Skill 再过滤；也不泄露其数量、标题或命中信息 |
| 交付主线 | History/Memory/Skill 回执与下一 Step Context 准入保持原方向；Tool Output 原文沿工具消息交付，不另建正文注入通道 |
| 内容与结论 | `complete-source` 只说明实际覆盖范围，不说明能回答问题；metadata 在用户确实询问它时可以是答案；原始片段足够时无需额外 read |
| 生命周期 | 原 Tool call/result 配对、Step/Attempt、取消、Lease、恢复、重复拒绝保护及 Budget 不变；没有后台搜索、额外模型裁判或第二个循环 |
| 工具副作用 | 只读回已经发生的输出，不重跑原命令。合成测试命令只允许在隔离夹具准备阶段按清单执行一次 |
| 资源 | 查询、扫描、分页、实际结果与完整模型请求均受限；不能因批量查询把扫描量、页数或输出上限乘以词数 |
| 泛化 | 不写领域同义词表、特定题号/答案/模型/域名分支、固定业务词、隐藏默认 ID 或来源；显式测试材料中的具体值与生产实现分开 |
| 结束判断 | 模型可回答、有限继续查或说明未解决；不对最终自然语言做正则拦截，不要求固定搜索次数，不把模型自评写成批准事实 |
| 协议 | 不预先升级生产协议。若候选改变冻结呈现或持久合同，先列影响矩阵；正式采用时走唯一新版本及明确旧数据拒绝，不静默兼容、迁移、改写或删除旧会话 |
| 本轮范围 | 不新增语义模型/reranker、Skill 隐藏正文全文搜索、万能 Reader、可变证据账本、MCP、Sandbox、Product/Workflow 能力或 UI 配置项目 |

生产化连接配置若随后需要，单独列出配置 owner 和验证范围；本计划的 RE-0 只为实验隔离网络，不暗中修改用户启动配置或系统代理。

### 4.2 首次真实调用前冻结

- 源码完整清单与摘要、实验改动 diff、运行器/材料生成器/评分规则摘要、解释器及实际依赖版本。
- 每题自然问题、材料、预期事实所在位置、合法来源、可披露范围、参考初始状态、答案与反例规则。隐藏来源的标准答案只进离线评分，不能出现在系统提示、目标问题或工具描述里；“复述当前消息”等对照题本来由用户提供输入，明确作为例外，不是检索答案泄漏。该说明已在首次真实调用前写入冻结 manifest。
- 按[grid-06 原冻结](../validation-data/active-retrieval/ar-d-grid-06/frozen.json)继承：`max_steps=12`、`max_output_tokens=2048`、temperature 0、请求窗口 32000、token 安全余量 2048、Provider timeout 60 秒、最多 3 次同请求 Model Attempt；其余各来源/Context 限额按原值完整复制入新 manifest，不抄漏或使用本机默认。
- 以上值是实验配置，不是新生产默认。运行时只通过既有授权加载器解析 Provider/model/endpoint，冻结脱敏身份；配置与预期不符时停止该批，不悄悄换模型。
- 单个活跃真实请求；按事先冻结的顺序交替 B0→候选、候选→B0，减少时间顺序混淆。不修改系统级 opener 或影响其他运行中的任务。
- 每臂、每题、每次重复都有独立 Session / EventStore / 工作区；同一对使用等价材料与相同资源。无法跨版本复用的准备状态分别通过原公开 owner 构建，不直接造一条“正确正文已送达”的事件。
- 使用完整 AgentRuntime/AgentLoop 主线，核对实际请求中的工具 schema 和候选呈现。单独调用 Provider、手工拼理想请求只能作机制探针，不能代替真实旅程计分。

准备步骤、模型摘要及目标问答分别记录成本。两臂准备结果如不等价，应记为准备/实验设计问题，不把这一对混入行为归因；仍保留它在计划总数中的状态。

## 5. 分组实验

### RE-0：基线、传输与材料冻结

**目标：** 建立可复查的新 B0 和共同网络条件，不修检索策略。

交付 B0 源码归档与摘要、实验 manifest、失败分类、开发题/留出题分组、脱敏传输诊断摘要。现有密钥只由原加载器使用，不读取原 `.env` 文本，不落盘认证头或有凭据的 URL。

在后续获准执行时，先做 2 个进程内直连探针：短回答及只生成工具调用的响应，各一次、无重试、45 秒超时，不执行模型返回的工具。任一失败则暂停真实行为批次，保留失败并检查网络；离线材料和 owner 检查可继续。探针只证明当时可用，不计检索成绩。

隔离 transport 必须实际经过原 Provider；若使用进程内替换，只可在独立实验进程中作用于网络入口，不能替换模型响应、重试分类或 AgentLoop。记录脱敏实际路由证据，禁用静默回退代理/其他 endpoint。执行后核对用户配置和生产文件未被改变。

### RE-1：工具输出的机器字段与业务正文

**假设：** 更清楚地呈现字段角色及正文是否加载，能减少 digest/exit_code 的语义混淆。

允许在原 Tool output / 工具自身呈现 owner 中，对已有字段作分区、准确说明与读取入口调整。先核对字段是否真实可结构化获得：只有工具自身明确提供的执行状态才可标作执行信息；不能在通用层用正则拆任意工具文本，也不能把正文改写成模型摘要。

原 `effect_id`、digest、原始 content/data、status 和控制回执保留；不以改短 ID、隐藏必需校验值、创建 handle 注册表或删除退出码换取分数。遇到无法无损分区的工具输出，保留其原有读取语义并报告限制。

六个开发场景槽位：两个业务代号与内容指纹干扰场景、一个业务码与退出码干扰场景、一个真实只问内容指纹的反例、一个真实只问退出码的反例、一个正文确实无业务字段的负例。旧失败仅取代表题，其他槽位使用明确标注的新合成材料。

观察：所答字段来自哪里、正文是否真的派发、误用机器字段次数，以及合法 metadata 问题是否退步。不要求用户问执行状态时也先搜业务正文。

### RE-2：Memory 来源级搜索入口

**假设：** 当前逐条 read_action 显眼，而整个可访问来源的搜索入口主要藏在说明中，促使模型只读已选背景条目。

候选只调整原 Context 导航：在 Memory 来源级给出搜索工具入口、当前展示范围与可用性；逐条读回入口继续保留。查询由模型依据当前问题及线索生成，宿主不把标准关键词填进动作。

准确数量只能由同一已校验来源快照推导；未读取或因限额不能获知时明确 unknown，不能为显示总数额外越权扫描。没有绑定、工具未暴露、来源不可用、合法范围确实为空必须区分；零自动候选时也能表达已有的合法搜索能力。

保持 Memory 批准、active 选择、自动排序、Top-K、正文 tier 和预算不变。若同时改排序，将不能判断是入口还是召回改善，应拆成后续实验。

六个开发场景槽位：两个目标被背景项挤出初始参考的正例、一个已有原文足够的正例、一个撤销/替代状态案例、一个项目无相应有效事实的负例、一个无绑定或功能不可用案例。跨项目/陈旧版本另由确定性 owner 测试覆盖。

观察：是否发现未入选的有效事实、是否沿已有线索搜索、是否仍只读背景后停；不得用“已经调用 search”替代答案和证据检查。

### RE-3：有界多关键词字面查询

**假设：** 允许在一次调用里给出少量不同字面词，可以降低单个词选错后放弃的概率。单有批量接口并不保证模型会选择合适的词，需要真实验证。

范围先限 `search_tool_output`，复用原输出 Reader/身份/扫描和附近读取，不把另外三种来源一起换协议。不同时改变默认大小写、排序、匹配语义或提供自动翻译模型。

实验候选参数为一个明确的字面查询列表：每次最多 4 项、合计 UTF-8 查询长度不超过继承的 512 字节；这些是待验证的显式实验限额，不提前定为生产默认。总命中、扫描工作与模型可见页必须有整次请求上限，不能每个词各领一份预算。若原 owner 无法证明这个边界，先完成设计而不调用真实模型凑结果。

每个命中可说明由哪些词命中，共用可验证原文位置和 read_action；游标绑定完整查询列表、顺序/去重规则、case 选项、part、源身份及策略。禁止改词复用旧游标，保留无命中、部分扫描、更多页、来源错误的区别。协议采用时只留一个清晰输入模式，不长留单词/多词双模式别名。

六个开发场景槽位：中英文词不一致、同语言短词/长词差异、一次直接字面命中、重复词或多个词命中同一位置、真正无命中、需要按命中读取附近。所有词由模型选择；人为给正确词的上限探针必须另外标注，不能计入自主检索收益。

观察：答案收益、查询词分布、实际扫描量、去重、附近原文派发、单词失败后的下一动作。批量调用还须报告“总查询词数”，不能仅因 Tool call 数减少就宣称查找更省。

### RE-4：结论与实际覆盖范围

**假设：** 在返回结果附近直观呈现既有范围，比追加一大段全局提醒更有利于模型判断何时可答、何时继续查、何时保留不确定性。

优先复用现有 `body_status`、范围、next cursor、匹配字段和来源可用状态，验证它们的呈现位置及歧义。若已有字段足够且无新可检验差异，记录“无有效候选”并停止该组，不能再造一个同义字段。

仅使用实际计算过的范围；不新增“整轮证据已充分”标志、全局阅读进度账本、宿主自然语言判断器或强制回查 Step。Skill 搜索仍限导航，不能把目录扫描完写成正文已扫描完。

六个开发场景为三组正反材料对照：Skill 隐藏章节、History 后页、Memory 初始范围遗漏。每组保持问题和可见背景相同，只改变合法原文是否含答案；不要只更换答案字符串冒充新场景。

负例允许在现有证据下说明“目前没有找到依据”，或明确根据主题作有限推断；无需遍历全来源才能停止。有答案题若仍只说“没找到”，答案维度必须失败。不能靠所有回答加免责声明获得通过。

### RE-5：组合候选与未用于调参的材料

只有独立组满足筛选规则的候选才可进入组合。组合后再冻结一次源码、合同及请求开销，不能边跑边改；不保证单项收益可相加。

使用 RE-0 已冻结、未拿来调参的 24 个新场景：每组机制 4 个共 16 个、4 个无需检索场景、4 个现有词法/准确来源直接回答保护场景。每组机制的 4 个必须含 2 正例及 2 反例/负例；合计按题型分别计分。

每个场景两次预定重复、两臂各运行一次，共 **48 对、96 个目标旅程**，准备与内部 Attempt 另计。新材料至少使用两个与旧题不同的主题，改变措辞、文档布局、噪声分布和事实类型；只换 seed/答案/ID 不叫新留出题。

一旦查看这些结果后改候选，该集合即成为已使用回归集；不得继续称为留出验证。不自动重跑原 72 题、修改旧报告或开始发布门禁。

## 6. 样本安排、评分与停止

### 6.1 小规模筛选，限定尝试次数

每个 RE-1–RE-4 候选先运行 6 个本组开发场景，加 4 个共同无需检索对照（问候、改写、简单计算、复述当前消息；工具仍暴露且有无关材料），每臂各一次：**10 对、20 个目标旅程**。

首次运行出现目标机制收益且未触发保护回归时，按已冻结安排对 6 个开发场景补一次成对重复，形成最多 **16 对、32 个目标旅程/候选**。重复结果全部计入，不按成功次数停止。两次重复不能当成独立新题或统计显著性证明。

每组最多两个具有明确不同机制解释的候选；第二个只有在第一个结果指出具体呈现/接口问题时才进入，不是换措辞碰运气。四组最多 256 个目标旅程，RE-5 最多 96 个，合计 **352 个目标旅程上限**，另有 RE-0 两个连接探针和明确记账的准备/内部尝试。这个上限不要求跑满，不允许自动扩张。

筛选规则：两轮均有净联合收益，且至少一个相同目标场景在两轮均从 B0 失败变为候选通过；收益应能从实际请求与行为链解释。合法 metadata、已有足够原文及无绑定等保护场景不得新增失败；共同无需检索对照必须答对且零检索/工具调用。任一保护失败时不宣称通过，也不补跑到绿色。

两轮样本不足以作普遍能力结论。未复现收益、收益只来自网络差异、效果互相抵消或只在一个故事成立，均记为“未证明可采用”，保留 B0。候选没有通过筛选时可以结束，不因用户 token 充足而无限调参。

### 6.2 每条分别记答案、证据、行为和执行状态

| 维度 | 判定方法 |
|---|---|
| 答案完成度 | 正例是否给出原文支持的所问事实；负例是否不编造；用户确实问 digest/exit code 时允许准确回答这些字段 |
| 来源与证据 | 在成功派发的真实请求里核对同 Session/项目、正确对象与版本、足够原文；搜索的原始片段已充分时可直接答 |
| 结论范围 | 全局否定是否超出实际检查范围；未查全时允许明确限定，不能把未查全本身判为必须继续搜索 |
| 行为 | 是否搜错来源、只读背景、误用元数据、同条件重复拒绝、盲目翻页或无必要检索；多词搜索逐词统计 |
| 执行状态 | 准备失败、TLS/超时、协议失败、取消、预算耗尽、正常回答分别记录；正常结束不代表答对 |
| 资源 | 全部工具调用及 search/read 子集、步骤、查询词数、源扫描量、页数、返回字符/字节/估计 token、Provider 已报告 usage、延迟和重试 |

固定分母主表保留网络/准备失败，同时给出两臂均正常完成的成对子集作为辅助分析；不能把 51/66 的旧辅助比例当成新实验基线。无答案题的保守表达不能替代正例完成度；附带错误断言另列。

离线人工语义审阅在可能时隐去臂标签，按冻结 rubric 看问题、合法材料、实际派发证据和回答；打分后保留解释再揭示臂。审阅不通过新模型裁判，不用答案字符串命中或脚本暂定 passed 作为唯一判断。

报告净收益对/退步对、每种失败的数量，按场景与重复分别展示。成本使用两臂可比较的完整配对说明；小样本延迟分位数只作描述。usage 未返回保持 unknown，不填零、不据此声称精确节省。

### 6.3 网络、组合及采用停止条件

- 任何实际越权、第二事实源、重复副作用、错误对象版本准入、不可重建请求或取消不收敛：立即停止该候选，先定位原 owner，不以成绩收益抵消。
- 在任一真实批次连续两条目标旅程最终因传输失败中断：暂停该批的后续真实调用，原有单请求重试保持冻结；已跑记录和未运行槽位均保留。检查网络后若另开批次，应重新标注，不能回填旧失败冒充同批通过。
- 网络失败落在关键收益对上导致无法归因，结论记 inconclusive；不单补成功臂或重跑该题到满意。
- RE-5 要求两个重复分别净收益为正，至少两个新场景体现收益；对每个拟采用改动，在它所属的新场景中也须有可复现的改善依据。所有边界检查、保护题和无需检索题通过，才可建议进入生产采用。
- 组合无净收益、只提升否定措辞却降低正例回答、反复增加无效调用或触发保护失败时，组合不采用；保留已验证的单项结论，不在同一留出集继续调参。
- 原 66/72 门槛、grid-06 结果和 NO-GO 不变。本实验的“建议采用”只说明改动有局部证据，不等于发布通过；最终合入生产、协议切换与提交/发布按实际授权处理。
