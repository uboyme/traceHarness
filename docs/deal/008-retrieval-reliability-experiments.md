## 3. 能证明的共性问题

1. **导航语义可能被模型当成业务事实。** RE-4 中，背景 Memory 明说“请查交接批准记录；本条不含具体值”，模型仍把“交接批准记录”回答成凭证。调整字段顺序未解决这一点；不能简单归因为原文没有保存或 Reader 找不到。
2. **搜到背景后停止，比完全没搜索更具体。** RE-2 的呼号题实际调用了搜索，结果显示只扫描了 2/13 个对象且有下一页；模型又读背景条目并停止。仅增加全来源入口不能确保它沿线索继续定位目标。
3. **多词只能覆盖选出来的词。** 首轮 RE-3 某题选择英文和中文词，成功找回原文；故障码题仍可只搜英文，然后把退出码 7 当成业务故障代号。重复对照没有稳定净收益。
4. **不可用与无命中仍可能被错误解释。** RE-2 候选实际拿到 `source-unavailable`，答案却说几个关键词都没有匹配。这是模型对状态的解释问题，本轮没有证据支持改写 Reader 权限或返回虚假空结果。
5. **明确资料能被正确使用，日常问题仍能直接回答。** Skill/History 中的充分原文、合法 digest/exit code 问题和日常保护题均提供了正向证据。不能因此改成每题强制搜索、强制读全文或统一拒答。

上述结论针对当前模型与冻结材料。零传输失败支持本批可以分析行为问题，不证明直连永久可靠，也不证明所有历史 TLS EOF 都有同一原因。

## 4. 评分与材料局限

- RE-2 的“备用集合点批准在哪里”可能被理解为批准信息存在哪里。该槽位保留在固定分母并明确标注歧义，不作为模型缺陷的因果证据。只看其余 9 个槽位为 7/9 → 6/9，去留结论不变。
- RE-3 停车许可证负例的回答先说“有”，随后引用“没有生成”。严格主表不把矛盾答案记作联合成功；即使两臂都宽松记为成功，首轮/重复的净差仍分别为 +1/-1，仍不满足采用条件。
- RE-2 基线无绑定题正确说明来源不可用，但附带了不准确的内部规则名和格式自述，保留为附加错误；若把它也严格扣为失败，RE-2 变为 6/10 → 6/10，仍没有收益。
- RE-4 候选 History 负例按“已提供的参考里无法确定”限定回答，没有证明全来源不存在，按冻结规则允许。它没有找到原文中的明确否定，是完整性局限，不能把这条算作检索成功。
- 人工审阅未盲化；没有模型裁判。小样本、同一材料重复和模型非确定性限制泛化结论。对有答案题，保守拒答仍算失败；对负例，不要求无条件遍历所有原文。
