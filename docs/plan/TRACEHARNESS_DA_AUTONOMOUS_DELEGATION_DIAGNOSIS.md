# DA 自主委派诊断：冻结实验合同

日期：2026-09-11。本轮获准定位零委派原因并进行有限真实测试，不提交、不发行、不自动采用，不运行全量 pytest 或 L2–L4。

## 1. 先核对旧证据

只读核查机制与开发批次的 30 个 adaptive trial：主方实际 dispatch 请求是否包含四项委派工具、描述及必要参数；原预算是否提供子任务数、深度、并发与费用空间；拒绝/失败/委派是否真的发生。必须按原执行 Session 身份读取，不能把无工具的 benchmark requester 当主 Agent。统计原材料体量，不根据零调用推断模型能力。

## 2. 三种条件

使用当前 Product 3 已验证安装源码，沿原 EvaluationRunner / Product evaluator、Workspace、Sandbox、Supervisor 执行。新任务材料和输出均在独立短目录，当前用户仓库不参与执行副作用。

1. **明确委派**：先实际读问题目录，再要求真实模型派只读助手核对一个独立问题，自己调查另一部分，收报告后完成交付。这只证明调用链和中途委派，不证明自主决策。
2. **自然复杂任务**：同一份实际源码材料，要求核对权限/来源、预算、取消及产物边界并给证据，不提助手、委派或并行。能自己做；是否委派由模型选择。
3. **简单任务**：从实际版本源码取当前版本写成一份 JSON。用于观察是否出现不必要委派，不能靠所有题强制分工提高委派率。

复杂材料为当前仓库选定模块的逐字节副本，不是把旧缩减题放大或填充无关文本；清单、源码摘要与原文件来源冻结。只允许创建答复文件，不改被调查代码。隐藏 Verifier 只验证文件未变、输出结构与证据行有效，不把结构通过冒充结论正确；结论另外对照原代码人工核读并标明评阅来源。

每种条件两次，共 6 个 baseline trial。实例使用已授权 qwen-plus / OpenAI-compatible 连接、直连、90 秒 timeout、每次请求最多 1 次尝试。工具使用原明确 Docker 配置，network=none，无插件额外授权。任务/主方/子方沿用前轮 600k/300k/60k Token 包络、120/60/16 steps、160/80/20 tools；其余预算值随 manifest 冻结，不临时涨预算。

先验停止：明确条件两次都无法委派时，先归因/修复调用链，后续未启动任务不冒充模型拒绝。若发现一般性装配/描述缺陷，可准备最多一个最小候选，冻结源码后复测相同最多 6 个 trial；不得按题名、模型名或答案硬编码，不改评分/权限/预算或自动采用。总任务 trial 不超过 12，总任务根预算上限 7.2M Token（实际用量另报）。无证据支持修补时保留原实现并报告限制。

## 3. 成功证据和解释

分别报告：工具暴露、真实委派尝试/拒绝、子 Agent 实际读来源、报告完成、父方成功请求消费精确报告、消费后继续执行、预算和取消收敛。自然任务须在未要求委派时出现该链，才说本例验证了自主委派；第一次调查之后委派，才说发生在中途。任务结论正确性、费用和延迟另列，不能用工具调用数量代替质量或收益。

固定两次重复均保留，不选成功一次当作整体成功。没有新 holdout 或 72 题重跑，不据这组小样推断跨模型稳定性。结束后由独立进程使用同冻结源码重开原日志/请求，复核与其他 Reader 串行，检验期间原文件不变。
