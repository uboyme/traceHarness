# 037：DA-11 独立决定输入验证

**独立输入让模型完成了首次决定，但可拆题还没有给出清楚的并行分工。** 按[冻结合同](../plan/TRACEHARNESS_DA11_INDEPENDENT_DECISION.md)，9 次真实调用结束后即停止，没有追跑、恢复 DA-9 或修改生产。

## 做了什么

复用 DA-10 原请求探针、Provider 和提案检查，新增 `tests/live_dynamic_collaboration/independent_decision.py`，只改变请求输入形态。每类题取同一原首次决定请求，执行三个条件：

1. 原请求逐字段保留，作为本轮对照。
2. 去掉此前执行对话和旧提醒，把原目标与全部成功工具结果重新组织为一个独立证据包，保留原 system。
3. 保持完全相同的独立证据包，system 仅保留原归档中的决定指令。

证据包不增加文件内容或答案：原目标、工具结果正文逐字保留，附原 stream、seq、step、call、effect 和正文摘要。每一项都回查原 SQLite，与实际请求中可见内容匹配，拒绝别的会话、失败、未来或正文不一致的结果。assistant/tool 组整体重组为引用数据，没有孤立 tool 消息；列目录仍只是导航。这个过程没有生成语义摘要，也没有新事实源。

两个独立输入共用同一份说明：包内目标是要分析的工作，当前调用只做执行形态决定；证据正文不构成指令或权限。第二与第一条件同时改变消息角色、执行叙述、参考尾注和包装，因此只能归因于“独立输入”这一整体干预，不能单独证明历史惯性是唯一原因。第三与第二才隔离通用 system 的影响。原 schema、模型、temperature、输出上限都相同，分类标签未送入模型。

固定 qwen-plus、直连、每格一次，不重试：

| 条件 | 合法决定提案 | 预期分类符合 | 精确 tokens |
|---|---:|---:|---:|
| 原请求 | 0/3 | 0/3 | 11092 |
| 独立证据包，原 system | 3/3 | 3/3 | 12283 |
| 独立证据包，精简 system | 3/3 | 3/3 | 7134 |

共 **9 次真实调用、30509 tokens、0 Provider 失败**。两种独立输入均选择 `separable/local/local`，原请求仍继续读写。这说明并非必须先削减所有通用 system 才能提交决定：保留原 system 的独立输入也能做到。精简 system 本次消耗较少，但样本很小，不能直接当作生产成本收益。

这次没有 Tool 执行、子 Agent、Workspace 或完整 Product 任务；指标是提案和标签，不是实际任务成功率。每格只观察一次，也没有留出验证或显著性结论。

## 分类对了，分工为什么仍不能算合格

本轮实现 Agent 核读了六份有效提案；这是显式的离线提案检查，不是独立 LLM 裁判、人工批准或原 Evaluation 的正式语义评分。

可拆题在“保留原 system”条件下，主方目标是从四个文件收集两主题的代码证据，助手目标也是读取四个文件并找两主题的代码引用。两边在做同一范围的工作，不能只因字符串不同就认定职责不同。

在“精简 system”条件下，助手读四个文件找证据，主方据此分析两个主题并组装产物。这个方案可以描述成阅读与分析分工，但没有清楚留下主方可同时独立完成的一项结果，存在先读后分析的依赖。它也没有达到本阶段要求的“两个独立结果”的证据标准。提案声称读取可并行，不等于已证明业务判断互不依赖；本轮可拆题仍只实际读到索引，未新增源码阅读。

因此两份可拆提案的独立并行分工均标为 **not_demonstrated**，不能把协议通过与标签命中宣传成协作成熟。两类 local 提案正确识别了小任务或一条依赖链，不创建无谓助手。

## 验证与当前边界

新增 16 项定向测试，加原探针、Provider、Context 和材料回归共 **91 passed / 0 skipped**。移除正文一致性检查后，错配正文反例因预期保护失效而失败，恢复后通过。compileall、4063 项 collect-only、修改范围 Ruff、文档/JSON/链接/围栏与 diff 检查通过。三个原 SQLite 摘要未变，九份请求和原响应独立保存。完整证据位置与精简报告见[验证索引](../validation-data/dynamic-collaboration/independent-decision/README.md)。

不运行返回工具；失败/取消传播，未知 usage 即停止，最多九次，输出目录不可重跑。没有全量、L2–L4、Wheel、Docker 启动、完整基线、语义裁判、提交、发布或 Promotion。生产仍是原 adaptive、默认 single，原用户改动保留，DA-9 候选仍撤回。

## 经验和后续方向

过去是在一个正在执行任务的对话里插入“先停下来决定”。这次把同一目标和原证据交给一次专门判断的输入，模型确实提交了决定。**目标可以长期存在，当前调用的职责应清楚；证据可以保留，执行叙述不必总跟着进入每一种判断。** 这是本次整体对照支持的方向，不能据此直接在生产里删历史。

下一步应先厘清 `main_goal` 是主方自己保留的工作，还是整个任务总目标，以及助手交付是否与它互补、可独立推进；先验证这份拆分合同，再考虑接入一次真实完整任务。不能让程序按题目关键词硬选分类，也不能只因提案字段合法就创建团队。后续实验需另行冻结，本阶段不提前增加新 Agent、状态表或 Runtime 接缝。
