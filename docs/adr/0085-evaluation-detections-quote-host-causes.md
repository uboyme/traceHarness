# ADR-0085：评测证据的工具失败检测附带宿主记录的原因

状态：**已决定**。日期：2026-09-24。收窄修订 [ADR-0082](0082-background-detect-and-propose.md) 中
“说明只含计数”的规定：这条规定只对聊天与 Product 发现继续成立。评测运行的 `tool-failed` / `tool-denied`
检测可附带有界的原因行。聚类身份、准入门槛、白名单、人工选择与采用门均不变。

## 背景

收口计划实验 C（[记录 087](../deal/087-task-type-context-evolution.md) §4）：

- 后台从 6 次开发运行中聚出 `tool-failed`（4 个来源）。
- 分析模型只收到“N 次工具结果失败”，于是提出泛化的“诊断错误、调整命令并重试”。
- 验证 3/5 对 3/5、token 比 1.001，不采用；它针对的 shell 启动失败也没有减少。

而被引用的 7 次失败，结果正文本身就写着原因：`sandbox_status=start-failed` 与
`FileNotFoundError: ... 'PYTHONPATH=src'` / `'cd'`。模型给按 argv 执行的 shell 工具写了 shell 语法，
检测把这条宿主已经记录的原因丢掉了。

## 决定

`detect(..., quote_causes=True)` 只由 `evaluation_findings()` 使用：

- 对 `tool-failed` / `tool-denied` 的每条结果取工具名、正文首行，以及其后第一条含 “error” 的行。
- 32 位以上的十六进制标识（回执、摘要）替换为 `<id>`，使同一原因在不同调用里读起来相同。
- 去掉不可打印字符，每条最多 200 字符。
- 按原因分组计数，最多列 4 种，附在说明里。

聊天与 Product 路径使用默认 `quote_causes=False`。那是用户自己的工作，工具结果可能含其文件或秘密，
因此仍只给计数。

读取范围只限宿主落账的 `tool/result` 正文，不读模型的推理或回答；原因来自开发题运行，
与验证题、隐藏测试和判分器隔离不变。

## 后果

- 第一次同条件复跑（C2，同 6 次开发运行）：`tool-failed` 聚类得到的建议点名 `cd` 与
  `PYTHONPATH=src`，要求直接调用可执行文件；上一轮是“诊断并重试”。
- 分析请求多出若干条有界原因行，仍受 `max_request_bytes` 约束。
- 定向测试：原因存在、分组计数、有界且单行；同一原因引用不同标识只计一次；聊天/Product 不引用。
  三项保护各经反向验证。

## 被否决的方案

- **在所有路径都引用原因**：会把用户会话中的工具输出送给分析模型，违背 ADR-0082 的隐私边界。
- **按工具名写专门解析（例如只解析 shell 的 stderr）**：把某个工具的输出格式写进检测合同；
  改为通用的“首行 + 首条错误行”。
- **附带完整工具输出**：无界，且会把大量无关内容送入分析请求。
