## 一个容易理解的真实例子

这是本轮显式测试故事，不是系统默认资料。四处都提到“设备交接核验码”，但含义不同：

| 资料 | 测试材料里的值 | 问这份资料时的实际表现 |
|---|---|---|
| 本会话临时讨论 | HST-W4R9 | 读取 History，答对 |
| 已批准的长期项目记忆 | MEM-J8L2 | 读取 Memory，答对 |
| 手册里的标准规程 | SKL-Q2P6 | 却读 Memory，错答 MEM-J8L2 |
| 巡检程序的原始输出 | OUT-D7N3 | 却读 Memory，错答 MEM-J8L2 |

已核对错误两题的实际请求：正确目录和读取工具都存在。问题不是手册丢了，而是模型把“批准过”误当成“可以回答所有来源的问题”。
因此下一步的一个有根据的实验方向是：让模型先确认用户问哪份资料，再判断该资料中什么内容有权威。
这次没有偷偷改提示后重跑，把这两条失败原样保留下来。

另一类真实错误也直观：用户问“程序返回的核验代号”，模型却拿输出文件的 digest 作答；
问“故障代号”，模型回答 exit_code=7。文件指纹和退出状态都是真实元数据，但不是用户问的正文答案。
三个 Memory 遗漏题则读完首批六条背景项就停；背景正文已提示去查另一份批准记录，但模型没有继续搜索。

完整 72 题的问题、原回答与逐题意见可直接看 [逐题阅读版](cases.md)，不用自己翻 JSON。
技术定位和验证细节见 [执行记录 021](../../../deal/021-unified-evaluation-ue4.md)。
