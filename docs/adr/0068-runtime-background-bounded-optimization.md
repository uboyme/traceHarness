# ADR 0068：运行期后台优化由宿主托管，复用原评估事实

状态：采用。日期：2026-09-11。承接 ADR 0066、0067 和 AO-3 合同。

## 决策

后台优化属于 `evolution` 的宿主控制面。TUI 持有一个应用生命周期内的 `BackgroundOptimizationHost`，只在用户启用的工作区中收集已结束 Turn 的结构信号或显式反馈。前台任务优先；原 AgentLoop 不导入优化器，策略插件不创建永久线程。

新增 `optimization-background:<workspace fingerprint>` 事件流，仍存于当前 EventStore。该流只拥有周期授权、观察准入、实验额度预留、结算位置、暂停和待审事实；以原 Store 的 expected_seq 线性化实验准入。Session/Effect 保留聊天与工具原件，Evaluation 保留分数和实际费用。投影不是第二事实源。

分析输入区分开发题观察和 `RuntimeObservation`。后者绑定 Session、Turn、截止序号与原证据摘要，没有伪造 case_id 或 gold label。自动信号仅发送工具拒绝/失败计数，明确可能是正常现象；用户说明是未经判定的反馈。完整聊天不自动上传，原工作区操作不回放到真实目标。

后台每次复用原 `run_strategy_optimization` 的一份提案、白名单字符串准入、两臂独立进程及模型审阅。跨轮候选摘要去重在评估前完成。初版只装配 source-isolated 检索旅程，评估数据和计划由用户显式选择，不自动创造评分标准。

周期累计实验数、完整 trial 数和分析/裁判 Token 预留。预留不退款；它不是实际 usage。每题预算仍由原 Runtime/Evaluation 执行合同负责。用量未知或收敛未证明时停止追加实验。新 ID、重启和冷却计时器不能重新发额度；续批需用户明确输入新截止时间，同额续批写入原流。

待审候选不自动生效。F6 可以查看状态、反馈、暂停、拒绝候选及续批；拒绝不等于采用。停止应用必须等待已拥有工作收敛；发现另一宿主或崩溃留下的未结算准入时不接管、不盲目重放。一次取消只通知原 worker 一次，重复关闭继续等待同一清理。

## 原因与边界

正常使用与离线实验之间缺少触发和生命周期管理，不需要第二套评估器或源码自修改。把调度事实单独归属而把评分和运行事实留给原 owner，可以持续尝试而不混淆权威来源。

第一版是应用存活期间的后台能力，没有 OS daemon。真实反馈可以帮助提出候选，但固定题上的提高不能自动证明已经解决该反馈；模型裁判仍可能误判。没有自动安装、提交、推广或在途热切换。DA 协作说明以后接入同一有限路径，不在本 ADR 提前实现。
