## 3. 本停止点发现并修复的验证缺口

1. **旧 Product 测试夹具误取用户输入。** `_ChatProvider` 把最后一条 user message 当真实输入，
   实际读到后置 Context，根本没有创建 ProductTask。现在同文件四个脚本 Provider 按 Runtime 的
   显式 metadata 与唯一 Context 后缀合同取得对话；Product 快照断言仍精确比较原 renderer 字节，
   仅同步位置。没有按正文、题目或示例名猜边界，也没有修改生产请求。
2. **TUI 测试断言早于存储完成。** `pilot.pause()` 只等待 UI 消息，不能证明 Git/SQLite owner
   已完成。先用原界面路径和实际 `on_mount` 信号独立复现，再将正式测试改为等待确认/结果页。
   继续验证确认与取消后的 durable head、active facts、零模型调用及关闭后拒绝访问。
3. **当前文档残留旧事实。** 更正 Context 前置描述、旧格式号与 Inspector 位置，目录说明改为
   四个示例包。前三个包有历史安装证据，第四个 Reference Skills 仍只有源码加载证据。

原失败全部保留：治理初检为 21 passed / 1 failed；首次 TUI 补跑为 5 passed / 2 failed。
这些没有被改分，也没有被称为干净 HEAD 基线问题。修复后原失败节点均重新通过。
