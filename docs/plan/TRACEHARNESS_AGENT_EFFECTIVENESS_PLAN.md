## 1. 最终目标与完成标准

最终交付是一个能用于简历和面试、可由真实证据复核的小规模实验结论：说明 TraceHarness 怎样在
保持原事实源、权限、预算和验收边界的条件下管理上下文、完成协作、试验并筛选策略。
不预设 multi 必须更快、压缩必须省钱或优化候选必须被采用。

| 目标 | 必须回答的问题 | 完成所需证据 |
|---|---|---|
| 上下文治理 | 是否在保住正确交付的同时减少整次任务成本？ | 一个主要因素不同的对照；固定验收结果、完整任务用量/时间、调用数、重复取证、折叠/读回与超限；原文可读和重放证据 |
| Single/Multi | 在相同资源授权下，协作的质量和时间收益是否覆盖分工、等待与整合成本？ | 同题同模型、材料/工具授权规则/固定验收相同、整树上限相同的配对；逐题胜负、失败阶段及全树成本 |
| 有界策略优化 | 有限搜索能否找到值得采用的分工策略？ | 开发轨迹、受限候选、停止记录、冻结后的内部验证、搜索和审阅成本、人工采用或拒绝结论 |

最终材料至少包含：冻结条件与证据索引、逐题结果表、三个问题各自的结论与局限、关键根因及取舍说明、
据此压缩的简历表述。所有提升数字来自可比试次；小样本和公开开发题身份必须披露。
零收益或负收益也是有效研究结论；未执行、证据缺失、取消未收敛不能包装成完成或通过。
阶段性结果可以先交付，但必须列出三项目标中尚未回答的部分，不能把工程止损称为完整收益验证。

## 3. 每轮必须从根因出发

### 3.1 修改或试跑前的最小记录

使用现有 deal/validation-data 记录和原事件索引，不新增运行时账本。每轮先填下表；根因未证实时
明确写“假设”，优先设计能区分原因的验证，不能为完成流程而编造确定性。

| 项目 | 必填内容 |
|---|---|
| 对最终目标的作用 | 本轮解决三个问题中的哪一个；结果会改变什么决策 |
| 观测事实 | case/试次/源码与配置版本、原证据定位、预期和实际结果、首次相关分歧 |
| 原因分析 | 所属 owner 与因果链；支持/反对证据；仍可能成立的替代解释 |
| 最小验证 | 能区分假设的最低成本方法；为什么已有证据或离线复现还不能回答 |
| 预期结果 | 具体观察量及成功/失败解释；不以“这次全绿”代替判据 |
| 范围与止损 | 允许改动、冻结条件、授权、调用/费用/墙钟上限、停止条件 |
| 运行后决定 | 支持、否定或仍未知；继续、转向或结束此问题；剩余全局阻塞项 |

优先顺序是原证据重读、确定性最小复现、受影响 owner 验证，最后才是必要的真实端到端确认。
根因分析区分以下情况：材料/固定断言错误、当前代码合同缺陷、分工与交付策略、上下文披露或读回、
Provider 延迟/传输/输出形状、预算和计量、报告/审阅路径。错误标签和最后一个异常不自动等于根因。

当前合同缺陷须按 AGENTS 给出公开路径、可观察错误、被破坏的合同及反向验证；收益候选则给出
可证伪的改进假设与代价。不能把设计偏好伪装成 P0/P1，也不能靠放宽完成或评分合同获得改善。

### 3.2 防止局部循环

1. 没有新的可区分假设、预登记复测目的或已确认修复，不追加同条件长任务试跑。
2. 初始研究止损规则：同一假设连续两轮没有新增判别证据或目标推进，暂停该路线的付费试跑，
   重新比较替代解释、实验设计和剩余预算。换参数或换试次名不能自动清零这个判断。
   这是一条研究管理规则，不新增 Runtime 计数器；需要调整时在下一批开始前说明理由。
3. 每个根因关闭后，以及每个预登记批次结束后，都回看三项目标：当前主要阻塞是否改变、此局部
   是否仍值得投入、最短可交付结论是什么。单项指标变好但完整任务不前进，不能继续按原路线惯性加码。
4. 连续外部传输失败先停止付费并定位连接或供应商条件；单请求已有重试边界不等于允许重跑整题。
   不用更大额度或更多重试掩盖未知计量、取消或生命周期问题。
5. 必要定向检查通过后进入约定阶段门禁；无新变化、失败或未决疑点，不反复扩大测试范围。
   这不免除 AGENTS 要求的集成全量、确定性失败修复后完整重跑和必要的反向验证。
6. 新增保护先回答“删除它会破坏哪条当前合同”；优先在原 owner 修复。无法回答时，保留为待研究
   假设或不做，不为假设建立第二状态机、第二事实源或无人消费的持久产物。

## 4. 分阶段初步方案

阶段允许因新证据调整顺序和缩小规模。跨出授权或改变持久协议时另行决策；改变实验条件须生成新版本，
不修改已执行批次，不拼接修复前后的运行来计算提升率。

| 阶段 | 工作与产物 | 退出或转向条件 |
|---|---|---|
| 1：单题交付与诊断 | 从已暴露开发题选一题；先取得 single 的固定 Verifier 裁决，再在冻结条件下诊断 multi；保留原 Patch、报告、费用和失败阶段 | 优先争取两种模式到达验收；证据和资源收敛可核验后，有界失败也可成为模式结果。反复阻断则按根因止损，不以“必须先成功”无限追跑 |
| 2：三题开发探索 | 在已有三题上选择一个上下文候选、验证必要的协作改进；条件稳定后用原 AO 搜索少量分工文本候选 | 每个候选得到支持/否定/未知及代价；冻结配置与最多一个进入内部验证的策略，或记录无候选值得继续 |
| 3：冻结内部验证 | 在未参与调参的预选题上比较 single、multi 基线，必要时增加优化后的 multi | 完成预登记范围或因停止条件结束；报告全计划覆盖和全部失败；不看结果后换题、改提示再补成绩 |
| 4：结论与简历 | 汇总完整成本、正确性、协作交付、优化搜索成本与局限，形成证据索引和简历表述 | 三个问题各自有证据结论或明确未完成项；不预设正收益，不继续追某个漂亮百分比 |

**阶段 1 先分清结果层次。** Verifier 已运行且通过、已运行但失败、未执行是不同事实；调用检查但
未进入有效断言也须单列。到达固定验收只说明流程走通，不等于补丁正确，更不等于完整 Product 成功。
Product/Workflow、Review、Approval/Promotion 和资源收敛继续读取原主线事实。
若已有冻结 Patch 可用于离线诊断，可单独检查补丁以区分交付阻断与功能错误；原失败运行不改分。
进入后续对照的硬要求是测量可信、资源收敛、用量边界可解释和预算可承受，不是所有开发题都必须解出。
若 multi 的有界失败已经说明当前策略不适用，可结束该局部改进；只有另一道预选开发题能区分新的
原因或适用条件时才继续，原失败题仍保留。安全、身份、账本或取消缺陷不能当成普通模型负结果绕过。

**阶段 2 当前转向。** 原先考虑并发长等待，但 ae04 的助手两次请求即完成；现证据不支持把它
作为这次慢的主因。当前仅生成一个避免重复调查的 ALLOCATION_GUIDANCE 候选，原生对照因
Provider 参数解析失败与未知用量停止，未采用。长等待、增量交付仍未实施，不为旧假设惯性加码。
Single 的收尾预留缺陷已修正；新的 shell 时间线与只读 profile 则定位到工作区快照使用过大 read
长度。优先验证这个原 owner 内的局部读取修正，保留身份/文件变化/总额度与发布前完整复核。
它不替代三项目标的最终对照，也不授权改变 Provider 持久合同；后者仍等待独立批准。

上下文对照在能够交付的路径上进行，可以先用 single 隔离协作影响。两臂保留相同硬上限与原文可读边界，
一次只改变一个主要因素；先考虑现有折叠配置，不能同时更换模型、任务、预算和提示后归因于压缩。
没有实际触发折叠的题，不作为长上下文收益证据；不得故意拉长对话凑收益。开发题上的配置选择结果
属于探索性观察；若预算不足以增加独立上下文验证，结论限于这些配对，不能借九题模式对照声称上下文泛化。

有界优化先限定为当前 Product AO 允许的 `ALLOCATION_GUIDANCE`，复用原候选校验、Evaluation、
Budget 和人工采用链。初步规模建议最多两个新候选；具体轮数、全部 trial/analysis 用量、期限、
连续无收益及重复/无效提案上限，须在启动前按原 AO 合同显式冻结，这不是框架默认值。
只使用开发失败轨迹，不向提案模型披露内部验证答案、结果或评分器；不改权限、门禁和评分追高分。
开发候选按原正式评估的完整证据、无已观测质量退步和预先明确的质量/成本门槛筛选，不仅按 token 少择优；
少量开发题上的“未观察到退步”不是统计学上的普遍质量非劣证明。
若原语义 Review 因完整仓库输入过大而阻断，单独定位并冻结最小审阅证据方案；不得跳过原 Review，
或用诊断性人工标注替代生产通过事实。完整软裁判校准另列，不自动扩成本阶段三十份产物的新项目。

## 5. 候选路线与转向依据

| 路线（均需按范围授权） | 什么证据支持尝试 | 最小边界与主要代价 |
|---|---|---|
| 并发长等待 | 主方已无独立工作，重复 collect/pending 产生模型调用 | 复用原 Supervisor 等待；身份、已授权截止时间、外层 ToolRuntime 超时须一致；取消等待不等于取消助手，不泛化放宽所有工具超时 |
| 收窄分工与报告 | 实际 assignment 仍要求全库穷尽取证，主方只需要其中一个有限决策 | 使用既有 goal/scope/exclusions/deliverable/briefing；整体任务验收不变；未完成不能伪装 completed |
| 折叠配置或披露调整 | 重复读取与已折叠证据有对应关系，排除引用参数错误等替代解释 | 使用既有预算、引用和重放；同时看完整任务成本，不永久豁免所有读回结果 |
| 当前 Turn 语义摘要 | 普通折叠与可读证据仍不足以保留工作进度，并有可区分的对照 | 单列摘要代价与错误；须设计原 Session 的合法切口、来源与重放，不把现有旧 Turn 摘要说成已支持 |
| 增量交付 | 有用发现反复因终局报告未交付而不能使用，较轻路线仍不足 | 先定义中途事实、最终完成、主方消费、取消与身份；复用原 Event/Effect/Artifact，不默认允许失败助手的部分结果通过完成门禁 |
| 换模型或推理配置 | 同任务的调用延迟/输出形状证据表明模型条件是关键限制 | 另开冻结实验；single/multi 同时保持可比模型条件，成本不能归功于协作改动 |

“看起来更聪明”“助手不愿意停”“推理 token 没进对话所以全是浪费”都不足以选路线。
多 Agent 时间重叠须按时间线计算；累计 Agent 工时、Provider 在飞时间、墙钟不能简单相加或互相替代。
若读回失败来自参数绑定错误，应先解决该边界，不直接增加摘要或扩大上下文窗口。
畸形采样的永久失败分类涉及持久协议，仍按交接文件列为独立架构决策。

## 7. 统一结果口径

逐题至少列：条件摘要、模式/候选、协作计划及交付状态、固定 Verifier 是否进入有效检查及结果、
Product/Workflow/Review/Promotion、失败阶段、输入/输出/推理分项、未知用量、费用估算、墙钟、
全树调用数、重复读取及原证据定位。已知费用和未知不能拼成精确总额；推理分项已包含在输出时不重复加总。
开发搜索另列提案、失败候选、审阅与最终比较费用，分别报告执行阶段收益和整个优化过程净成本。

完整任务成本包含所有角色、失败、取消与重试；纯等待轮次、引用绑定错误、完全相同调用的重复、
分页和不同范围读取分别统计，不能把合法分页全算浪费。重复读取统计说明原结果此前是否被折叠。
阶段指标用于解释，主结论同时呈现正确性与成本，不能靠提前失败取得“更省钱”的结论。

逐题表是主结果；报告计划分母、已执行分母、有效配对和缺臂。未开始属于覆盖缺口，不记为模型解题失败。
成功率列分子/分母；每成功任务费用为全部已执行费用除成功数，零成功时未定义。若只在双方成功的题上
比较耗时，必须明确这是条件子集，并同时保留全部计划结果。少量重复不增加独立题数，不预承诺显著性。
内部验证揭盲后发现的问题可进入下一轮开发，但该批不再作为下一轮未见验证；不能继续调参后重用它证明泛化。
