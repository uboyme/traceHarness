# 三项亮点的面试讲法（阶段稿）

## 主线

我把 Single 作为主力，Multi 作为需要证明收益的可选执行方式。系统目标是让长任务有预算、
有正确性裁判、能追踪失败原因，而不是用更多 Agent 包装一次模型调用。

## 上下文治理

大工具输出外置、闭合 Step 折叠、软硬水位和按需原文读回共用原事件与请求证据。
评估同时看整任务 token、调用次数、最终验收，避免只看单次输入变短。
当前两道开发题的配对观察分别减少 9.6% 和 4.4% token，但均未通过固定验收，
第一题还增加了 20% 调用。第三题两臂都通过，但没有触发折叠，不能用于归因；
原定三题六试次完成，仍不能声称正确交付提效。

## Single 与 Multi

astroid 的同条件单次对照中，Single 完整通过，Multi 25/26、token 多 50.7%。
助手两次模型调用已完成，根因不是笼统的“不肯停止”，而是主方重复取证与补丁语义遗漏。
因此保持 Single 默认，不给简单问题强制分工，也不把个案推广为 Multi 永远无用。

## Single 有界自进化

优化对象是白名单内的 CODER_GUIDANCE 文本。真实模型从开发失败轨迹产生候选，
原生双臂执行同题、固定裁判；候选被冻结后在另一题验证，采用另需批准。
第一版加强检查范围反而超时；从实际轨迹发现 argv 工具误用管道、验证过宽和收尾后继续取证。
第二版约束这些行为，开发对照 token 减少 6.6%，但两臂验收失败，不能当作优化成功。
在预先选定的 pvlib-1154 上，双臂均通过，但 token 增加 12.7%，费用增加 3.2%；
一次工作时间减少 9.5% 不满足原成本门槛，最终拒绝采用。该题此后明确降为新一轮开发题。
第三版针对验证题上更宽的检查成本重新开发，但双臂均失败且成本退步，按规则停止，
没有伪装成独立验证。三轮 Single 开发与首题验证的已知费用合计 4.953771 元，
另有取消未知费用保守预留 18 元。全部计入 120 元上限；没有宣称搜索净收益。

## 能明确承认的边界

公开 SWE-bench Lite dev 的 12 题完成材料准入，不等于 12 题完成 Agent 运行；
内部验证也不是官方未见测试集。每组只有一次，不能声称统计显著或稳定平均收益。
事件重放、文件级 Ownership、单进程 Supervisor、可信进程内插件均有明确能力边界；
没有把这些边界在这轮实验中包装成已经实现的分布式、语义合并或插件安全隔离。

## 追问时回到证据

执行完成、固定验收、资源收敛、批准采用分别记录；模型自报完成不是成功证据。
每次失败先读原事件、原补丁和固定 Review，再决定属于工具合同、代码语义、上下文或宿主耗时。
不连续微调到出一个好结果才报告，不改裁判，也不删除失败试次。
