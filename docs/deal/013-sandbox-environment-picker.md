# 013：沙箱环境下拉选择与手动填写

## 目标与归属

用户不应手工查找并抄写镜像 hash。改动属于 TUI 配置层：Docker 连接和镜像提供只读发现、下拉选择与
手动输入，最终仍交给原 `parse_sandbox_config`，保持格式 2、固定镜像身份和原执行 owner。
不涉及镜像构建／下载、运行时标签解析、自动选环境或新增持久化协议。

## 当前实现

- `tui/docker_choices.py` 只查询 Docker context/image 列表和选中镜像的 ID、OS、自动挂载卷元数据。
  同一镜像的标签合并展示；未命名镜像用短 ID 区分。候选值是精确 ID，不把标签当作持久身份。
- `tui/config_forms.py` 在原配置表单增加刷新和下拉框，同时保留手动输入。用户点更新后采用输入；
  手填标签解析一次，保存时复核固定身份。连接变化清空旧镜像，失败刷新清除旧候选，没有默认候选。
- 使用有界临时文件接 CLI 输出，避免 Docker Desktop 派生进程持有管道导致无限等待；每次 10 秒、
  输出最多 1 MiB；取消停止查询并通过原 `await_worker_convergence` 等待，不留下迟到保存。
- 原文件变化检查与原解析器仍在最终写盘前执行；错误、取消、过期文件不覆盖用户文件。
- Docker 未声明 Volumes 时按缺省无卷读取。实际 Docker 测试先复现 Go 模板直接访问缺失键的失败，
  改为读取可选键后复测。未声明卷不意味着 Python 或项目依赖已经验证，执行器仍负责执行时检查。

## 数据与边界

没有迁移、删除数据，没有添加协议兼容层，没有改变 SandboxPolicy 或执行器。用户现有工作区配置未改动。
镜像名称只用于选择，原配置和回执保留完整身份。仍不承诺恶意宿主插件隔离、自动安装依赖或其他后端支持。

## 验证

定向测试覆盖下拉／手填、标签变化、连接切换、原文件保护、失败／取消、CLI 超时和输出限制；
真实本地 Docker 覆盖发现、标签和 ID 解析以及 Textual 下拉到配置文件保存。
最终计数及编译、收集、Ruff、文档检查见 [本轮证据](../eval/sandbox-picker/checks.json)。
没有执行全量、L2、镜像构建／下载、真实模型 API，也没有提交或发布。
