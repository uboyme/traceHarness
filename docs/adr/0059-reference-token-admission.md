# ADR-0059：参考资料使用完整请求的剩余 token 额度

状态：E2 已实现并通过定向、反向与真实验证，2026-09-09。扩展 ADR-0056/0058；不改变资料资格、人工批准与唯一事实源。

## 顺序与所有者

RequestBuilder 先按既有字节资源边界准备候选草稿，给原 CompactionService 检查完整压力；维护完成后，
再由 ContextInputService 用同一个 RequestTokenMeter 进行最终参考准入。摘要步骤不带参考资料。
这样不会先删除参考、掩盖原本可通过收起旧历史解决的压力。没有第二份模型上下文或 Provider 生命周期。

## 冻结预算与来源证明

沿用 context/input 的 budget.token_measurement，明确区分 unavailable（未启用 token 策略）和 estimated。
estimated 记录计量器身份、完整 TokenBudgetPolicy、固定请求部分指纹与估算、剩余参考额度、当前参考消息估算。
固定部分来自当时 Composition 加 observed_session_seq 截止的原 Surface，包含 Product、历史、当前用户输入、
完整工具组、工具定义和可见封装；不能压缩的当前问题回显也必须计入最终参考消息。

Context payload parser 用冻结编码、策略和最终实际渲染文本重算数值，拒绝伪造额度或半个块；source reader
按冻结额度复核相同优先级。正式 read_context_input 在取得同一步已冻结 Composition 后，重新从原事件截止点
构造固定部分并比较指纹和估算。因此伪造的固定部分不能通过请求构造、Session permit 或精确重放。
不把完整 Composition 或可变消息复制进另一份持久账本。最终 E0 完整请求计量及硬上限仍是 dispatch 前的门。

这属于现行 Context 格式内一个明确判别的预算形状；未配置 token 的合法模式继续使用 unavailable。
不猜旧记录、不补写预算、不静默迁移。无法取得冻结计量器或其版本时明确拒绝重算。

## 准入规则与导航

沿用新显式阅读、实际保留正文、自动 History、检索排序后的自动 Skill/Memory 优先级。
逐候选检查完整渲染后的消息 token，而非用字节除常数或累加可能不一致的正文估算；同时保留每类/单块/总字节和数量边界。
块必须整体进入或整体排除；新的 token 排除原因与旧字节排除原因可区分。当前问题回显不能为了凑额度消失。

原本有资格且被自动检索选中的小导航，可在同一资料的显式正文装不下时保留；不伪装成该正文已经披露。
已经读入正文时不再重复放同一自动导航。只有既有资格来源能产生导航；不借 fallback 编码隐藏 Skill 正文、
引入跨项目 Memory，或延长首次披露失败后的保留授权。纯目录也装不下时明确省略，不能承诺任何预算下都可导航。
实际 token 排除由原 Context exclusions 生成明确宿主说明，提醒回执不等于正文交付，不要原样重复申请。准入预留普通与排除两种完整渲染说明的较大需求，最终只记录实际使用的一种；依据真实 History 循环失败修正，不按模型或领域特判。
模型参考说明需区分“有目录”和“正文已经读入”；宿主详情列出排除原因。不得仅改 UI 展示裁剪实际请求。

固定内容和最小必需消息本身已超过硬上限时，允许生成零参考的审计快照，由 E0 如实记超限并拒绝；
不能因 E2 的零参考额度绕过硬上限，也不能把错误包装成成功回答。无按模型名推断、自动配额或新公开配置默认值。

## 验证要求

真实 Runtime 覆盖 token 窄额度但字节足够的排除、正常正文准入、新阅读优先、保留逐出、导航保留、
固定 Product/工具/当前问题受保护、额度伪造拒绝、取消/失败、冻结重放和两项 load-bearing 反向验证。
真实模型在隔离项目中读 Skill/Memory/History，核对实际请求、token 估算/usage、正文证据与副作用次数。
313 项最终定向测试与两项反向验证通过；六组真实对照及冻结重放通过，见 [验证报告](../validation-reference-token-budget.md)。E3 的可读超限体验随后实现。
