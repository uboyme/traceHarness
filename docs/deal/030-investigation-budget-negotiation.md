# 030：只读助手额度申请与显式续派

本阶段直接实现原 DA 后续的有限额度协商。没有继续外包给 Claude，也没有增加第二套 Agent、Workflow 或预算状态。

## 改动与边界

- Product 配置版本 4：必填助手初始 Token，独立于创建时冻结的累计硬上限。宿主给主方和助手装配各自的额度工具。
- Budget schema 3：初始分配和批准/拒绝沿原账本记录；父方余额、在途预留、收尾保留量、子方上限一起约束拨款。
- 成功申请沿原 Session 留下部分进展和待办，Continuation 直接结束这一轮。父方收集精确证据、决定，再显式 followup；不会自动加钱、自动继续或重置消耗。
- 停止和取消仍沿既有 owned 生命周期收敛；关闭账户不能续派，旧申请不能用于新工作。

详见[执行合同](../plan/TRACEHARNESS_INVESTIGATION_BUDGET_CONTRACT.md)。旧 Product 1–3、Budget 1–2 明确拒绝，不迁移或删除历史数据；旧实验仍由对应冻结源码查看。

## 真实模型结果

只运行一次明确的协商练习，真实子模型为已有授权连接的 `qwen-plus`，直连、无代理、最多 4 次调用；父方是确定性脚本，走原 Product factory、SQLite、Git worktree 和现有 Docker 沙箱。

实际顺序是：助手列出文件、读取 `tracked.txt`，申请 5000 Token 并带回“文件内容为 base”的进展；申请轮以 `investigation_budget_requested` 收尾。父方沿工具批准，将初始 20000 增至 25000，累计上限仍为 30000；显式 followup 后，助手完成报告。原 Product 捕获产物、通过检查并停在人工审批前，没有执行推广。

真实子方 4 次模型调用，输入 14107、输出 376，共 **14483 tokens**。本轮 4 个 Session、15 份请求离线重开核验通过，其中 4 份属于真实子方，其余是确定性 requester/主方。没有重跑模型来补报告。预算在途预留为零；本次停在审批前，原 Product 仍保留 3 个已登记工作区，`aclose` 不等于审批完成后的 `release`，未宣称这些目录已删除。

此结果**不是自然申请策略或协作提分证据**：任务明确要求练习申请，主方决定由脚本给出；申请时剩余额度仍可工作，不能证明额外 5000 是必要花费。拒绝、取消、并发等边界由定向测试验证。

首次离线审计驱动误给 `SurfaceProjector` 传入构造参数，导致报告步骤失败；执行已成功，修正驱动后只重开原数据库审计，没有重复真实请求。保存的运行源码摘要为 `462c45202c46e1faa6d69e74528a7d90b3f1c01483bb33ede2809f6b62ccf6bd`；之后生产源码仅调整一处类说明文字，行为未变。源码归档摘要与精简证据见[验证摘要](../validation-data/dynamic-collaboration/budget-negotiation/summary.json)。

## 定向验证

初始定向批次 277 passed / 3 skipped；跳过项为未在该批次提供显式沙箱配置的集成测试，随后在显式 Docker 配置下另测集成。核心相邻复核 123 passed，新增 Product 批准/拒绝主线 2 passed；批次有重叠，不能累加当独立总数。最终显式 Git/Docker 相邻集成 25 passed，新增停止后读取决定的收尾检查批次 16 passed。按测试身份去重并以最终结果为准，合计 **302 passed / 0 skipped / 0 failed**。全仓仅收集 4019 项，没有执行全量。

两项关键反向验证：临时去掉父方收尾保留量检查，公开拨款路径错误接受额度；临时去掉累计上限检查，满额账户错误接受追加。两次均由对应新测试得到预期 `DID NOT RAISE`，随后逐字节恢复生产实现并重跑定向测试。

执行 compileall、全仓 collect-only、修改范围 Ruff、diff 检查与文档对应/链接检查。未跑全量测试、L2–L4、Wheel 或旧 benchmark；没有提交、推送、发版或改变默认 single。
