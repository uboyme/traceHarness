# AO-3：宿主运行期后台受限优化合同

状态：限定实现与验证完成。沿用 [总体设计第 13 节](TRACEHARNESS_UNIFIED_EVALUATION_AND_OPTIMIZATION_DESIGN.md)。

## 1. 职责和事实源

`evolution` 拥有后台周期、反馈准入、跨轮配额、冷却和暂停。Chat/TUI 负责用户输入与宿主生命周期；AgentLoop 不导入优化器。策略继续调用原 `run_strategy_optimization`，评估与审阅继续拥有答案、成本和候选比较事实。后台记录进入现有 EventStore 的工作区作用域流，以 expected_seq 为准入线性化点；没有另一个数据库或可变 JSON 状态机。

真实反馈为 `RuntimeObservation`：绑定工作区内已完成 Turn 的 Session、截止序号和证据摘要。它是未经判定的问题线索，不是 benchmark case 或语义 gold。未经授权不上传完整用户轨迹；自动观察只包含工具执行计数等结构信息，用户反馈包含用户明确提交的说明。原文留在原 Session/Effect。

## 2. 周期与调度

用户显式开启一个有截止时间的额度周期。额度包括实验次数、完整 trial 数和分析/裁判 Token 预留。每次先预留完整有限实验，不退款、不因新 ID 或应用重启补充额度；界面明确区分预留上限与原证据中的实际 usage。每题执行预算继续由原 Evaluation/Runtime 合同负责。未知成本或未证实收敛停止后续实验。

同一工作区仅一个活动实验。新的前台工作先取消并等待后台收敛，再调用模型。暂停/退出必须等待原分析、评估 worker、Generation 和裁判结束；重复取消不能泄漏工作。重启发现未结算准入时明确阻塞，不重放实验或用户工具副作用。

观察按原证据身份去重，候选按原 patch 摘要去重。等待审阅期间可以继续收集观察，但不追加候选实验。无新观察时等待；无收益冷却。周期额度耗尽或过期必须显式重新授权，不能周期性自动重置。

## 3. 实验与产品入口

后台使用用户选择的冻结 benchmark/run-plan 和获准说明文本节点。原用户工作区不作为评估写入目标。真实观察辅助分析；质量结论只来自原评估合同，不能声称直接证明修复了未经标注的真实问题。

TUI 提供可读配置、状态、反馈、暂停和恢复入口，配置生效不改变在途 Step。生产继续运行当前批准版本。候选只输出可审阅报告与修改；本阶段不实现自动采用、源码自修改、OS 常驻 daemon 或 DA 多 Agent。

## 4. 验证

定向验证原有 AO 调用、跨宿主竞争、重复反馈、重启额度、取消及失败、scope 拒绝和原证据重开；关键保护反向验证。真实验收必须经过 Chat 完成、反馈、后台调用、原独立评估和重新打开证据，不以伪造 callback 成功替代。只运行相关测试、收集检查、Ruff、compileall、文档门禁；禁止全量 pytest 和 L2–L4。

实现及证据未齐之前不标记完成、不发布。此合同中的额度均为用户输入；测试驱动数值只属于显式实验。
