# ADR 0067：独立模型语义审阅与人工采用分离

状态：采用。日期：2026-09-11。承接 ADR 0066 与 AO-2，不改写此前人工审阅阶段的记录。

## 决策

程序继续检查原事实源、实际证据派发、预算、执行完整性、作用域与资源收敛。语义审阅可由显式配置的独立模型 Session 执行，按冻结 rubric 评价答案、归属、完整性和否定范围。采用候选仍由用户决定。

模型不能因给出“通过”就越过硬门禁；有答案题没有实际证据时，程序直接拒绝通过。模型失败、格式错误或精确用量未知，保留 pending_review 并停止本次审阅，未完成项不删除。

`evaluation` 继续拥有 review/assess/comparison。新 `model_review` 是原审阅器的执行适配器，不是第二套 evaluator；`model_review_protocol` 负责构造独立裁判输入、解析并核验实际模型判断。judgment 格式升为 2，明确 origin=human/model，模型来源绑定原 call/Session/请求及摘要。格式 1 明确拒绝；需要对旧执行补审时，从原执行重新 export 格式 2，不自动改写旧判断。

`model_service` 用原 Runtime、AgentDirectory、BudgetLedger、Provider 执行一次无工具控制调用。它供优化分析与语义裁判共用，Session 各自独立；`model_evidence` 只读重建实际请求、原答复、预算及 usage。调用方保留主错误和 cleanup 错误，重复取消只向同一任务通知一次并等待收敛。

## 原因及边界

精确值匹配不足以判断回答完整性和否定范围；模型判断又不能替代可执行硬约束。因此两类判断分别保留身份和证据，不能把 LLM 结果伪称人工审阅，也不能把最终采用交给评估器。

提案插件只得到显式开发观察及允许编辑文本；裁判获得该题 rubric、预期、原答案和真正到达请求的证据，不获得显式原版/候选标签或提案理由。可见证据按相同内容去重，不重复塞入每一步的完整历史；使用原 answer_dispatches/dispatched_context 验证来源。

同一种远端模型可用于提案、执行和裁判，但各自独立 Session 并不意味着统计独立；模型裁判可能有共同偏差。小样本只能发现流程和候选问题，不能声称稳定泛化提升。源码和评估条件冻结，远端模型 revision 若不可取得仍记未知。最终报告分列试验、分析和裁判成本。

不增加自动安装、Git 提交、Promotion、动态 Workflow、多 Agent 协作或插件进程沙箱。一次策略入口只生成一份候选；后续新实验需要新的显式输入和目录。
