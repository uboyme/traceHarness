**字段说明改变了提案形式，但没有得到有用的独立分工，本轮不采用。** 按[冻结合同](../plan/TRACEHARNESS_DA12_COMPLEMENTARY_WORK.md)，完成六次真实配对后停止，没有改提示追跑或接入生产。

## 修改及原因

DA-11 证明独立输入有助于提交决定，却没有证明分工合理。核对原 schema 后发现，main_goal、child_goal、child_deliverable 只有类型和长度，没有字段说明。因此本轮只在诊断请求里补这三个已有字段的 description，其他所有字段、工具总说明、system、用户目标、证据和模型参数保持相同。

- main_goal：local 时是全部自己做的工作；separable 时是主方真正保留、能独立推进的结果，不是总任务或只负责等候/汇总。
- child_goal：有边界的只读独立结果，与主方互补；两边无需等待另一方未来结果才能开始，允许共享背景。
- child_deliverable：助手自己负责问题的可核对答案、证据和未知项；不是给整个任务收集所有片段。

说明原文随[证据 audit](../validation-data/dynamic-collaboration/complementary-work/audit.json)保存。没有加字段、改枚举或验证器，也没有案例词、来源路径或分类答案写入这些说明。`tests/live_dynamic_collaboration/complementary_work.py` 复用 DA-11 原来源回查和 DA-10 Provider/提案检查，只观察返回提案，不执行 Tool。

## 得到的经验

“名字不一样”“可以同时开始”“字段合法”都不足以说明分工有用；还要看助手交付是否承担用户目标中的实质结果，而不是为了满足形式条件另造小任务。这需要语义核读，不能用字符串不等或关键词分类替代。

当前可拆输入仍只实际读过索引，任务结构证据有限。继续加字段说明没有证明有效；下一步如果继续，宜单独验证补足两个主题的实际源码证据是否改变分工，并保持当前说明固定，区分证据不足与分工能力限制。该实验尚未实施，不应直接恢复强制检查点、创建新 Planner 或宣称多 Agent 可发布。
