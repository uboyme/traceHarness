# AO-2+：语义裁判校准实验，候选未采用

2026-09-11。限定实验已完成；新裁判策略未达到冻结门槛，生产 `model_review_protocol.py` 已逐字节恢复到 AO-2+ 开始前。没有改变搜索、预算、权限、评估协议或人工采用入口。

## 1. 这次做了什么

先核对 AO-2 的 18 份原答案及实际派发证据，找到 4 份仅凭目录/主题就断言全文不存在的答案。其中原裁判误放了 3 份。程序原有硬门禁仍能挡住另一份“缺少实际派发证据”的正例。

随后冻结 12 个开发输入：8 个原答案、4 个明确标注的合成对照。涵盖目录否定、Skill 正文和资源、Memory、History 完整搜索片段、保守否定、错动作和漏动作。每种裁判各判断两次，两个条件交替顺序；题目、答案、参考值和原证据相同。开发标签在调用前固定，不发给裁判，也不称为独立人工 gold。已经查看的旧验证组不再视为未见数据。

候选只改 evaluation 的说明和输入呈现：利用原 diagnostics 字段解释目录搜索覆盖范围，强调回答完整性，在被引用的问题前后标明“当前任务是评判答案”。原 Runtime、Budget、Session、model review、assess、comparison 主线不变。

首个实验在第 9 次调用停止：裁判返回被评问题的答案而非 status/reason。保留这 9 次原记录和费用，再按[事前合同及有界修订](../plan/TRACEHARNESS_OPTIMIZATION_AO2_PLUS_CONTRACT.md)执行一次最终对照。最终对照中，已完成且用量明确的无效输出计为失败观测，不重试；生产审阅的 pending 即停止规则没有更改。

## 2. 真实结果

使用现有授权的 `openai-compatible / qwen-plus` 直连，两条件温度、预算、模型一致，无隐藏重试。单次 64,000 token grant、2,048 输出、2,048 安全余量、90 秒期限，实验上限按合同保留。

| 48 次固定对照 | 原裁判 | 候选裁判 |
|---|---:|---:|
| 符合冻结开发预期 | 16/24 | 15/24 |
| 错误放行 | 7 | 6 |
| 错误拒绝 | 0 | 3 |
| 待审/输出不合协议 | 1 | 0 |
| 两次结论不同的样本数 | 1 | 1 |
| 精确 tokens | 146,462 | 171,217 |

候选未通过要求 24/24 符合预期的冻结门槛，总体一致数也低于原条件，成本更高。不能因个别改善而采用，也不能据此宣称搜索成绩变化。这是有重复的小型开发诊断，不是独立统计准确率。

| 全部本阶段真实调用 | 次数 | 精确 tokens |
|---|---:|---:|
| 首次中止实验 | 9 | 56,502 |
| 最终固定裁判对照 | 48 | 317,679 |
| 对原 18 份答案走原 review/assess/comparison 复审 | 17 | 120,664 |

原复审另 1 份由硬门禁直接失败，没有调用模型。74 次 Provider 执行均完成、用量明确、资源收敛，没有连接失败。两次不合协议输出属于裁判行为问题，不能删掉成本或混成网络失败。

实验复审给出的开发双臂分数为 2/4 → 3/4，原验证组为 3/5 → 4/5；这 18 个判断中只有 13 个符合本次 Agent 合同审核标签，仍有 2 个误放和 3 个误拒。因此这些数只说明未经认可的裁判会怎样评分，**不能用于宣布候选搜索变好**。AO-2 原 3/4 → 3/4、5/5 → 5/5 的工件保留；没有修改旧 assessment，也没有加分到旧 72 题。

## 3. 用例与经验

以下均是显式实验例子，不是系统默认。

1. **目录没有命中，不代表正文没有。** 档案手册的原回答声称“没有车辆加油折扣码”。候选识别出搜索只覆盖标题/摘要，纠正了这个误放；但邮票规范的同类否定仍被放行，裁判继续用主题和字节数推断正文。这说明范围字段送达了，模型却未稳定遵循其含义。
2. **参考值类型不是用户输出格式。** 问人数上限，回答“上限为 27 人”有已批准的 Memory 原文。候选两次都误判必须只写 `27`；History 中回答口令和交接位置，也被一次误判为只能写口令。固定 rubric 没有这种只输出单个值的要求。
3. **答对一个字段不等于完整。** 问口令和按钮，只答“应报口令 RILL-682”被候选两次放行。原可见正文还明确要求按蓝色隔离钮。裁判在理由里把单值 expectation 置于完整问题之上；“口令正确、按钮写错”的对照则能识别。单值参考与多项问题之间的关系需要更明确。
4. **待审也是测量结果。** 原裁判有一次输出了题目答案，没有输出裁判 JSON；另一次也因去回答被引用问题而被解析为待审。前后标明裁判任务后，本轮最终候选没有格式失败，但不能把这个局部结果等同于语义可靠。

经验是先用同证据对照区分“信息没有送达”和“送达后解释错误”。本轮两条件原证据逐字段相同，强化说明确实修好一处，也制造另一处。应保留反例和失败候选，不能只展示那道修好的题。

## 4. 交付与架构边界

- 保留 `tests/live_optimization/calibrate.py`、`calibration_inputs.py` 和 `reopen_calibration.py` 作为显式实验驱动，调用原服务；不是新 evaluator、插件或产品入口。当前生产源码拒绝将原裁判冒充历史候选运行，需使用归档的对应冻结源码。
- 候选源码、候选测试及全部真实运行归档；新层级解释函数与提示没有留在生产模块里。校验记录见[恢复证明](../validation-data/unified-evaluation/ao2plus/policy-restoration.json)。
- 原事实源、投影、请求与人工 Promotion 边界不变。独立裁判 Session 不等于独立模型能力，也不等于人工批准。
- 本阶段不增加强模型、多数投票、自动纠错、后台优化、Workflow、MCP 或沙箱功能。不继续改题、标签、门槛追分。

若后续继续，优先显式区分“问题要求的全部事实/动作”“用于定位的参考值”“可支持的断言范围”，用独立审阅的新对照再验证；这是后续建议，尚未实现。

## 5. 验证与可复查性

全部 **74 个 Session / 74 份请求**从原 SQLite/Effect 重放通过，428 个实验文件在重放前后不变；原 AO-2 实验的 1,523 个文件与先前归档逐字节相同。恢复生产策略后，原 4 份 assessment 可以重开；实验 4 份 assessment 因策略绑定不同被明确拒绝，使用实验冻结源码时已核验通过，没有兼容旁路。
