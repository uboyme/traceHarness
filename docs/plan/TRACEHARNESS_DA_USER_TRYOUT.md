# DA：只读助手与后台优化逐行体验

本文用于 DA 工作区开发版；已经发行的 v0.11.0 包只有 AO-3，不能把本文的 adaptive 配置交给旧包。例子和路径由你选择，不是系统隐藏默认值。当前 DA 工程与有限实测已完成，尚未证明模型协作更好；完成范围见两份上下文 12.12。

## 1. 先用新的测试目录和配置

准备一个已有提交、可以放心修改的 Git 测试项目。Windows 下使用较短的项目与评估输出根目录，避免 Git worktree 管理文件超过路径长度限制。不要用旧 Product 数据目录继续测试新协议；旧记录保留，仍可用对应旧版本查看。当前 Product 任务/配置是协议 4，Budget 是 3，Product 状态快照是 format 8。

在该项目目录启动已安装当前源码的 `traceh`。连接配置完整时进入聊天；否则先填连接向导。按 **F2** 打开配置，选择 **任务执行配置**，使用界面生成的新草稿。

| 界面项目 | 怎么填 |
|---|---|
| 任务执行模式 | 第一次选“单个编码角色”（single）；第二轮选“主 Agent 按需委派只读调查”（adaptive） |
| 要处理的 Git 项目 | 当前测试仓库的绝对路径；起始版本选你要测试的已有分支或提交 |
| 结果接收仓库 | 用一次性本地 bare Git 仓库；不要填生产远程地址 |
| 接收分支 | 与这个接收仓库实际分支一致的完整名称，例如 `refs/heads/main`；这是例子，不能猜你的分支 |
| 审批人署名 | 你自己可辨认的名字 |
| 完成后的验证方案 | 该项目实际可运行的小范围检查；每个参数分开填写，不把整条命令塞成一个参数 |
| 主 Agent / 只读调查助手模板 | 保留界面草稿的读写分工；主方可写，助手只能列目录、搜索和读文件 |
| 委派后为主 Agent 至少保留的 token | 保留正数，让主方还能整合结果；助手预算、主方预算和整个任务预算一起核对 |

再配置 **执行沙箱**：选择已有 Docker context 和本地镜像，保持网络关闭。允许的读写路径要覆盖这个测试项目需要的内容。模型调用的网络连接与工具沙箱的网络是两条边界；沙箱网络关闭不意味着模型 API 也关闭。

保存并应用配置。配置页负责编辑和校验，保存不等于启动任务或后台实验。

## 2. 第一轮：看简单任务是否自己完成

在聊天中逐行发送（请把函数名称替换为你项目真实存在的函数）：

```text
请检查这个项目中的一个小函数，修复它对空输入的处理，并执行对应的小范围检查。保持改动最小。
```

检查宿主给出的 Proposal：源码、版本、模式、任务内容符合你的意思后，按界面说明在确认处输入大写 `START`。这是启动授权，不是给模型的一条新问题。

按 **Ctrl+B** 展开/隐藏任务面板，按 **Ctrl+T** 打开任务对话，按 **Ctrl+D** 查看真实改动。single 应只有主 Agent；adaptive 处理这种简单题也允许不派助手。**“用了几个 Agent”不是通过标准。**

程序验证通过后应停在人工审批处。检查补丁与验证记录，再决定批准或拒绝；模型说完成不会自动修改接收分支。

## 3. 第二轮：观察按需调查

在另一份相同起始提交的测试任务中，选择 adaptive，再提出涉及两个独立来源的真实问题，例如：

```text
请定位这次输入校验错误：一部分线索在配置读取流程，另一部分在执行入口。先查清两边的调用和约束，再由你统一修改并运行相关检查。
```

这是自然任务示例，不保证模型一定委派。若它派了助手，在 Ctrl+T 中核对：

1. 每个“只读调查”有不同 Agent/Session 身份以及明确目标、交付要求。
2. 助手只检查任务起始版本，看不到主 Agent 尚未提交的改动。
3. 主方收集的是精确消息的报告，可以追问或停止不需要的调查。
4. 报告“已完成”和“主方已收到”是不同事实；助手结论仍需由主方判断。
5. 主方结束时，所有助手先停稳，再产生补丁、验证并等你审批。

如果模型没有委派，只能说明这次它选择自己做；不要把没有子 Session 的运行说成多 Agent 成功案例。当前真实小样尚未证明 adaptive 优于 single。

## 4. 第三轮：看取消是否停稳

启动一个确实还在进行的测试任务，在任务面板执行取消。待宿主确认收尾后，再打开任务状态和对话。

检查主方与助手都不再继续产生执行记录，取消/失败和已有成本仍保留，接收分支没有被自动推广。不要靠删除输出目录判断“已经清理”；持久记录本来就应该保留供核查。

## 5. 后台优化怎样开启和查看

F2 中打开后台优化配置/选题页，明确选择自己的冻结 Product 题库、题目、执行沙箱和实验额度。Product 优化使用 adaptive 对 adaptive，只改四个委派说明常量；原始代码、验证、评分、权限和预算不属于优化器可改范围。题库应代表你的需求，不能把一次聊天答案直接当标准答案。

先保存计划，再按 **F6** 查看后台优化并显式启用该额度周期。它等待可用反馈和前台空闲，受周期次数、Token、任务数、冷却及到期时间约束，不是无上限不停调用。前台恢复工作时应优先让路。

看到实验报告时，分开看程序硬验证、语义判断、整树成本和失败原因。**候选可供审阅不等于已采用**；没有收益可以保留原版并停止。采用权限始终归你，不会因为后台打分高就自动改你的运行策略或源码。

## 6. 一句话区分几件事

ProductTask 管“这次工作允许做什么、何时验证和批准”；adaptive 管“主 Agent 是否借助临时只读助手”；Evaluation 管“原版和候选到底表现怎样”；后台优化管“在明确额度内自动试一次改进”。它们复用原始事件和资源 owner，没有第二套任务账。

助手预算可在 F2 设置初始额度与累计上限；部分进展、批准/拒绝和显式续派见[额度申请合同](TRACEHARNESS_INVESTIGATION_BUDGET_CONTRACT.md)。示例数字不是隐藏默认值。
