## 2. 关键根因与最小处理

- **交付预留接线缺失**：Single 没有应用已配置的收尾预留；其他角色按比 Turn 更长的角色时限
  计算。已在原 Product 策略接线修复，绑定最早截止。六条真实主线测试与两条反向验证；修复后
  首次获得本轮完整 Single 成功。预留不是模型一定做对的保证。
- **局部指标替代整任务指标**：提前折叠降低峰值与总输入，却增加取证调用；保持候选不采用，
  不继续围绕一个更低的水位反复调参。
- **协作内容重复**：主方读过源码后再分配同段调查。当前证据反驳“所有慢都因子 Agent 不愿停”，
  但不足以证明一个提示补丁能普遍修复。早期候选限制 ALLOCATION_GUIDANCE；当前 Single 候选改为 CODER_GUIDANCE，未增加交付协议。
- **参数语法失败终止长链**：两臂原 Provider 都记录固定参数解析错误，原始生成文本未保留，
  不能还原具体错误语法。该批触发停止并保留证据；用户随后授权新冻结批次，仍每请求一次 Attempt，未实现采样重试。
- **宿主耗时**：ae03 模型活动约 140 秒，9 个 shell 工具区间累计约 298 秒，含沙箱准备、
  文件处理与收敛；其中容器运行仅 10.50 秒，准入至 request 110.67 秒，outcome 至 publication
  117.73 秒。对 ae02 保留工作区做只读 profile，375 文件/3.2 MB 的快照约 15.02 秒，read
  占 14.58 秒。同字节单文件读取对照显示，按工作区剩余额度 read 需 17.31 秒，按已知文件
  大小加 1 需 0.062 秒。修正后原 snapshot 一次测量为 0.256 秒，29 项回归与三个反向反例验证通过。
  这是局部读取改进，尚不等于整任务已提速，安全复核没有省略。
- **Windows 路径**：原生嵌套实验在模型派发前 Git checkout 报 Filename too long。
  离线原入口复现后改显式实验输出位置，不改通用代码默认，不删除失败记录。
