# 工具参数畸形采样：待批准的最小决策

日期：2026-09-22。状态：设计建议，未实现、未新增付费调用。

## 当前事实与根因

有界策略评测的原生 baseline/candidate 分别在第 19/11 次付费尝试出现
`protocol / provider-tool-arguments-json-value-expected`，原生优化器以
`evaluation-usage-unknown` 停止。两侧均收敛；原始错误响应未保留，不能断言具体参数内容。
084 §10 已明确这属于待决策的宿主失败分类边界。它不是上下文越限，也不是助手拒绝停止。

当前适配器在解析工具参数时抛出异常；即使 HTTP 响应中另有合法 usage，当前失败结果也不携带它。
后者必须用离线有效信封/畸形参数夹具验证，不能仅凭线上缺失 usage 断言供应商返回了 usage。

已完成公开 `OpenAICompatibleProvider.complete` 的本机 HTTP 离线探针：相同合法信封和
7/3 usage，合法参数返回 exact usage；畸形参数会先抛出 protocol 错误且 usage=None。
非法 usage 加畸形参数也没有被误记为 exact。见
[探针证据](../validation-data/agent-effectiveness-v1/provider-failed-usage-offline.json)。
这证明当前控制流会丢弃合法失败用量，不证明线上两次失败确实返回过 usage；不得补写历史数字。

扩展探针还证明 `finish_reason=length` 配合截断参数时得到同一 JSON 错误，结束分类在抛错前未
保留下来。因此不能仅凭现有线上 failure_code 判定是正常采样语法错误还是输出截断。
修正必须先保存并使用已验证的结束分类：截断、拒绝、未知结束仍走当前不完整响应边界，
不能被参数解析错误掩盖后当作普通采样重试。只有正常结束的参数语法错误进入下述候选范围。

## 推荐范围

1. 在既有 ProviderFailure 与 model/attempt-end 主线上，明确区分响应信封协议错误和模型生成的
   工具参数语法错误；仅正常结束且经白名单识别的参数语法失败可以作为有界重采样候选。
2. 信封缺失、字段类型错误、身份不匹配、未知错误仍失败关闭；不能泛化为所有 protocol 可重试，
   不能接受任意 Python、宽松 JSON 或执行畸形工具调用。
3. 若批准，先设计并版本化实际受影响的持久合同，保留唯一事件事实源；不静默改写历史记录。
4. 每次重采样仍是独立 Attempt，走原预算预占/结算/取消；合法 usage 独立校验后可进入失败尝试
   记账，缺失或不可信 usage 仍未知，绝不填零。只有证明当前预算规则可安全覆盖，才允许最多一次
   额外采样；不能先放宽重试再补账。
5. 验证必须覆盖合法响应、参数畸形、信封畸形、非法 usage、两次失败用尽额度、取消和重复结算；
   对关键边界做反向验证。检查点完整通过后，冻结新的实验版本；原失败保留，不回填成成功。

## 原停止条件如何恢复

需要用户明确批准该宿主合同变更和在剩余 120 元总额度内恢复真实调用。
没有批准时继续离线门禁、分析和简历事实更新，不启动九题验证或重跑已失败题。
批准不是让原生优化器忽略 unknown：优化对照仍须完整可比、原重放/不变量/收敛通过才产生结论。

原 C4 还规定任何 Provider 失败记录都停止。即使实现了重采样，也不能暗中把“最后成功”当作
已经满足原规则。若获批准，新实验须另行预登记唯一例外：仅明确参数语法错误、失败 usage 已可靠
   结算、最多一次额外采样且最终恢复的尝试可以继续；失败尝试仍全额计入成本和失败率。
未知用量、重试用尽、坏信封及其他原停止条件仍停止后续批次；原 C4 文件和原运行结论不修改。

采样错误的用量若未知，必须在额外派发前拒绝重试。当前“一份冻结请求的不可观测预留”规则
不能被当作多个可能收费的完整响应只算一次的依据；合法 exact 失败用量须按每个真实 Attempt 结算。

## 代价与不承诺

这是一个失败分类与记账边界修正，不增加增量交付工具或新的 Supervisor。
不能保证模型第二次生成正确参数，也不能保证 multi 获益；仅避免把可识别采样错误与坏信封混为一类。
若离线检查证明需要更大改动，停止扩大范围，记录新的决策点。
