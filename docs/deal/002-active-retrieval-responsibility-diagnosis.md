# 主动检索职责定位与小规模对照

当前为诊断阶段；AR-D 的 NO-GO 不变。本记录中的语料、编号和种子均为显式测试材料，不是产品默认。

## 1. 现有失败的共同表现

按 grid-05 的 27 条候选失败逐条核对原请求、工具调用和最终回答，每条只归一个主要行为类别：

| 行为类别 | 条数 | 应检查的责任边界 |
|---|---:|---|
| 把退出状态或存储指纹当作所问事实 | 9 | 工具输出呈现与模型字段理解 |
| 局部证据推断全来源不存在 | 9 | 搜索覆盖说明与模型停止判断 |
| 选择了错误来源的工具 | 4 | 工具发现、上下文导航及测试策略拒绝反馈 |
| 读到背景资料后提前结束 | 4 | 来源发现与模型继续检索判断 |
| 分页耗尽步骤 | 1 | Memory 候选排序、片段预算和查询选择 |

这是行为归类，不是已经证明的因果归属。逐条身份见
[diagnosis.json](../validation-data/active-retrieval/ar-e-output-01/diagnosis.json)。

默认 Continuation 在没有工具调用且没有失败的可选 Verifier 时结束；`completed` 不保证证据充分。
目前没有自动语义证据裁判。`next_cursor`、无命中、正文是否足够由模型解释，搜索工具不会自行继续搜索。
不将这个既有完成合同当成新的实现 bug，不新增强制读取状态机、第二事实源或按题目关键词决定结束的规则。

## 3. 对照 02：最后参考包的来源导航

检查发现系统提示包含工具输出读取说明，但 Context 最后的来源导航只列 History、Memory、Skill；
token 模式的“回执后正文没出现”也未明确限定为这三类披露回执，工具输出实际直接在工具消息中交付。

在隔离源码副本中补充工具输出导航和直接正文位置，并限定回执说明的适用来源。
只验证这个交付说明假设，不修改生产 Context 协议，不把原工具正文复制成第二份事实。
同问题、同预算、同模型，再跑全新 12 对任务；运行中不调整材料和说明。

原版 3/12、候选 5/12，字段误用为 6/5 条；新增通过集中在种子 113，新种子的故障代号仍被答成退出码。
两个附近读取问题都因重复选择被拒绝的文件工具耗尽步骤；原版这两条同样答错，但没有耗尽步骤。
导航改动实际进入候选全部 12 条目标请求。负例通过都核对了完整原输出搜索无命中，不能只凭答案措辞计分。

独立重开 24 个会话、130 个请求精确重放，不变量/重放错误和未结束 Attempt 都为 0；原命令每条只执行一次。
130 个结束 Attempt，服务报告 720821 total_tokens，未知/估计 usage 均为 0。
[完整结果](../validation-data/active-retrieval/ar-e-output-02/summary.json)。

**决定：暂不合入探索性的 Context 修改。** 有局部收益，尚不能证明稳定的通用改善；不能把 5/12 当作修复完成。
候选只存在隔离源码和证据中，生产全部 Python 文件与 grid-05 候选的冻结摘要完全一致。
当前 Session 11 / Context 10 未变，实验请求须用对应冻结源码重放，不能由生产 reader 冒充兼容。

## 4. 保留的边界

搜索片段如已包含来源有效、足以回答的原文，允许直接回答；不因名为 snippet 就强制再读。
错误身份、批准状态、版本、Lease 和取消仍由既有 owner 校验，模型回答正确性不能由这些校验冒充。
未切换模型、未启用语义检索；模型强度与接口因果仍需进一步区分。用户数据、Profile、协议及 Git 历史未改变。
本次新增的是显式诊断运行器和证据，不是默认启动配置；没有例子内容进入生产隐藏默认。

## 5. 职责判断与后续切入点

- **已验证：** 正确调用工具输出搜索时，可以从原 Effect 取回所需事实并进入真实模型请求；独立重放一致。
  本轮没有复现搜索命中后被宿主丢弃的确定性缺陷，不能据此把所有剩余问题判给存储或 Reader。
- **行为证据：** 存储 digest、进程 exit_code 被当作业务值；知道预览不完整仍停止；被拒绝后重复同一文件调用。
  默认 Continuation 只执行既有停止合同，不自动审判这些回答的证据充分性。
- **需要分清的测试边界：** 当前隔离评测的 SourceOnly 拒绝工作区探索，但这些工具定义仍对模型可见，
  拒绝说明要求使用配置的来源。这是现有冻结评测条件；不能偷偷移除工具、改拒绝反馈或改题后声称旧分数改善。
- **下一项最有区分力的调查：** 明确记录“工具定义可见”与“本次调用获准”的差别，单独验证来源选择和拒绝反馈。
  若要改装配或错误协议，应作为新的独立假设对照，沿原 Policy/Tool owner 实现，不按问题词表或某个模型分支写规则。
  语义检索无法直接纠正把退出码当答案，因此不是这批问题的优先修复点。
