# WC-4 命令说明与启动失败反馈修复

2026-09-13，用户授权继续改善。针对记录 062 的真实失败，修改原 ShellTool 说明与原 Sandbox guest 启动错误输出，没有新增真实模型调用。

## 根因与修改

ShellTool 本来就以 shlex.split 解析参数，guest 直接 Popen，不解释 shell 语法。旧说明仅写 argv，未充分说明当前工作目录与操作符；guest 又捕获 ValueError/OSError 后直接 finish(start-failed)，丢失错误原因。因此模型只收到空 stderr，无法从回执得知 cd 被当作不存在的程序。

现在工具及 command 参数说明明确：当前目录已是隔离工作区，直接调用程序并使用相对路径；引号用于参数分组，cd、&&、管道、重定向和变量展开不会自动解释。启动失败先看 stderr 再纠正调用。没有解析器特例、命令改写、自动重试或新增 shell 权限。

原 guest 将启动异常类型和实际消息写入既有 stderr，按原 output_bytes 字节上限截断；原 finish 继续负责收敛，状态仍为 start-failed、exit_code 为 null。原 CAS、Sandbox outcome、Tool failure 和后继请求携带同一错误，不新建字段或事实源，不改协议。旧记录保持原样；这次没有修改 Provider、AgentLoop、预算、取消、文件发布或人工 Promotion。

## 验证

真实 Runtime → Tool → 已有 Docker 镜像 → 原账本/CAS → 后继模型请求的四种定向情形：误用 cd、另一不存在的程序、文件无执行权限、长程序名错误限长。均核对失败、无发布、原证据收敛及错误可见；随后正确命令实际写出文件，请求重放与不变量通过。模型替身用于确定性编排，没有付费模型调用。

进程内反向移除 guest 错误写入，实际错误调用和随后成功写入仍发生，但新测试因后继证据缺少 FileNotFoundError 而失败；恢复正常代码复测通过。没有临时回滚工作区文件。

定向与相邻门禁共 70 项不同用例通过，包含原真实取消/孙进程回收、stdio、固定验证、Product、发布及架构检查；其中四个新用例在反向验证后再跑通过。compileall、4209 项 collect-only、三个 Python 文件 Ruff、文档与 diff 检查通过。只使用既有明确镜像，不拉取、安装或跑全量/L2–L4。

## 结果与限制

通俗例子：按钮原来只说“启动失败”，现在会说“找不到这个程序”或“没有执行权限”，同时说明按钮直接启动程序，不是一个终端。模型仍自由决定下一步，程序不替它修命令，也不保证模型不会再犯错。
