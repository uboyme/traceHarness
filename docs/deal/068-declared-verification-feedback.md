# 通用验证反馈：公开声明、执行身份与未知原因

2026-09-13，按用户授权实现 [ADR-0076](../adr/0076-declared-verification-disclosure.md)。不是发票任务修复：生产代码没有新增业务类型、文件名、示例数据或模型特判。

## 修改

- 原 VerifierCommand 新增 public_requirement，宿主显式声明检查要求；JSON 必须给出字符串或 null，字符串有界且拒绝控制字符。
- 命令/计划摘要绑定公开说明，Promotion/验证协议为 3，旧 1/2 明确拒绝。配置入口立即冻结校验，活动测试材料与 benchmark 校验值同步；历史试次原样保留。
- 原可写 completion 先核对计划和结果身份，再在原 verification/result 内反馈公开说明、实际命令结果、未知根因和输出未保留事实。不把私有 stderr 当可检索材料，不推断内部断言。
- 原固定验证、候选观察、取消收敛、Artifact Review 和人工批准边界保持。没有新增输出读取权限、自动执行额外检查或新账本。

公开说明必须由宿主写准。一个命令检查多条要求时，失败只能归到这个命令，不能假装已经定位到其中某一条。若要细分，应在原计划中明确多个独立命令。

## 验证

227 项不同定向/相邻检查最终通过，覆盖不同业务的真实客体检查、公开/私有配置、旧协议拒绝、说明影响摘要、替换命令结果拒绝、完成失败与返工、当前候选变化、取消及原批准推广路径。初次检查暴露新测试的异常文案匹配、CAS 夹具布局、配置入口延后校验、活动 benchmark 摘要及架构白名单未同步，均已修复并定向复验。

反向验证在独立进程绕过命令 digest 核对，真实客体检查已经执行，替换结果进入完成反馈并继续到正式 Review；新增测试按预期失败。正常实现拒绝该替换，原完成门禁的正向、返工与取消测试通过。compileall、4230 项 collect-only、修改范围 Ruff、文档链接/章节/Mermaid 及 diff 检查通过。未把多次集合重复计数，也未用模型自述充当证据。

本轮未调用真实模型、未跑全量或 L2–L4、未安装或拉镜像；未提交、推送或发版。记录 067 的真实失败不被改写为通过，新的反馈尚未证明能改善真实模型成功率。

通俗例子：配置检查可以明确说“必须包含声明字段，这项检查失败了”，计算检查可以说“声明的求和条件通过了”。框架不会因此声称知道具体哪行有错；保密检查则明确说明没有公开诊断材料。
