# AO-3：把已有的有限实验接到正常使用之后

状态：限定实现与验证完成，进入用户已授权的提交和发行。对应 [AO-3 合同](../plan/TRACEHARNESS_OPTIMIZATION_AO3_CONTRACT.md) 和 [ADR 0068](../adr/0068-runtime-background-bounded-optimization.md)。

用户在 TUI 按 F2 选择后台优化题库、双臂计划、额度和到期时间，进入聊天后按 F6 开启。之后已完成聊天中出现工具拒绝/失败，可形成仅含计数的待核实线索；也可以在 F6 对最近一轮填写反馈。

后台平时等待，有新线索且额度允许才调用原 AO：模型提一份说明文本修改，宿主检查允许范围，在独立进程跑原版和候选，调用原语义审阅器。结果可能是没有候选、没有改善、待审或失败，不预设必须涨分。实验只用选定隔离题库，不回放用户工作区的写入。

举例（仅解释流程）：回复找到了手册目录但没读正文，用户提交这条反馈。后台可以提出更清楚的读取说明，再检查冻结题库是否改善。改动只保留为候选；当前聊天继续用已批准的版本。反馈不是标准答案，题库成绩也不自动证明这个具体问题已经解决。

周期和预留写进原 EventStore；实际回答、证据和费用仍查原 Session/Effect/Evaluation。重启不补额度、重复反馈不再执行、同一候选不重复评估；前台开始任务会先等待后台取消收敛。F6 暂停、待审拒绝和显式续批均不具备采用权限。
