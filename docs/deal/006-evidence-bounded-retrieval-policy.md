# 006：主动检索的证据导航、真实反例与边界

日期：2026-09-09。范围：当前 AR 后续问题定位；已修改呈现并完成定向验证，**未达到“自主检索全面可靠”**。不改变 AR-D 分数或发布门槛，不运行全量、L2–L4、安装、Wheel、发布或 Git 提交。

## 根因与最终修改

同一问题在隐藏来源“有答案”和“无答案”时都回答“没有”，证明模型可以靠主题或预览猜题。共性问题不只是检索词选错：Skill 摘要没有与其他来源一致的内容性质/读取动作；大工具结果的前缀会被当成整份日志；读取页虽有 next_offset，模型仍会把第一页当全文。

最终保留三个生产文件的本轮修改：`session/context_input.py` 增加 Skill 导航/正文标记及精确目录请求；`session/tool_output.py` 改大输出呈现并声明页范围/字面匹配；`session/protocol.py` 升到 Session 13。原 `runtime/prompt.py` 已恢复到本任务开始前的提示，**没有保留提示词重写**。

没有修改检索算法、Scope、批准、索引、原文事实源、循环停止条件或预算上限。导航不能代替授权；search_skill 仍只搜目录字段。旧来源内容仍由 Reader、状态仍由 Projection 解释。程序能证明“这页从哪里到哪里”，不能证明自然语言回答在语义上充分。

## 实验边界

沿用用户已授权的真实连接配置，经原 profile loader 调用 OpenAI-compatible/qwen-plus；不读取或输出密钥。每轮在调用前冻结源码、脚本、原问题、材料、预算与权限。源码 ZIP、SQLite 原账、事件导出、完整回答和重放报告在各实验目录。

正反事实示例均为显式合成测试，不是默认配置：保持同一句“归档检查是否给出了保险理赔编号”，一份隐藏输出没有该字段，另一份在后部放 `CF-55C0AB6241`。手册对照只改隐藏章节，不把答案或工具名加进问题。补充部署回滚与泵站工单两个领域；后续再用这些题时明确视作已知诊断集，不能再称独立留出集。

`provisional_joint_pass` 只用于有答案题，要求实际原文证据与回答一起满足检查。负例不因“碰巧说没有”自动通过，也不因增加工具次数自动通过。局部未命中、来源明确否定和未解决分开审阅。

负例的重要结果：最终导航候选读到了“未批准回滚”和“未创建工单”的明确原文；原 Skill 无答案题仍根据主题扩大为全来源不存在，应记为未解决的问题。最后输出候选在无该字段时实际做了关键词搜索，但“没有给出编号”没有明确限定字面查询范围，仍不能把它当作已证明所有可能表述都不存在。

共执行 122 个目标问题实例，含真实准备共 625 次 Attempt。已知 usage 合计 3,430,669 tokens，其中输入 3,373,605、输出 57,064；另有 26 次 usage 未知，**不是精确账单总量**。两个最终失败为 provider-tls-eof，保留原失败，没有丢弃或重跑到成功后覆盖。各轮本来允许的 Provider Retry 同样留在账本，不能把最终失败数量等同于全部传输异常次数。

## 工程检查与未采用尝试

最终 owner 84 项、直接相邻 owner/协议/架构 221 项，共 305 个不同定向用例通过。新增测试在公开路径核对：模型真正收到的摘要导航动作、未泄露正文、实际执行一次的大输出、四种读取/搜索工具组合、异常/超时结果同样保留、读取末页仍是片段。既有取消、Result 恢复、错 Session/指纹、原始数据与独立重放检查保留。

三个进程内反向实验分别恢复旧摘要呈现、旧大输出前缀、旧读取页，均在已发生的公开请求/结果上触发预期断言；恢复后对应检查通过。没有改运行中的真实实验源码，也没有以导入失败或未发生操作冒充反例。

早期“末尾提醒”候选还暴露过默认空 Context 的预算计算错误：新增固定尾部没有纳入 empty policy 的精确模板长度。该候选整体撤回，当前 empty policy 与实际模板重新一致；没有靠扩大生产预算解决。一次缩短模板的临时副本也未采用。失败日志保留，不计入最终通过数量。

compileall、collect-only、修改范围 Ruff、diff 与两份上下文的章节/链接/Mermaid 检查通过，见[验证汇总](../validation-data/active-retrieval/evidence-navigation-validation.json)和[文档检查](../validation-data/active-retrieval/evidence-navigation-doc-qa.json)。所有真实实验用各自冻结源码在另一 SQLite 备份里独立重放，601 份请求重建、事件不变量与来源核对均无错误，无新 Provider 调用。详见[机器汇总](../validation-data/active-retrieval/evidence-experiments-summary.json)。

## 经验与下一项边界

1. **先查模型实际看到什么。** 请求快照、回执、已准入正文和最终回答要连起来看；“代码支持搜索”和“模型实际找到了”是两回事。
2. **正反事实比单个成功例更能揭错。** 同一句话只换隐藏正文，才能识别靠标题或常识猜对的情况。
3. **呈现应明确范围。** 导航、原文片段、全文和字面未命中各自说明；EOF 只能说明本页结束位置，不能证明扫描过全部历史。
4. **模型多想一次不是保证。** 这次真实复核没有稳定改善，所以不把可变计数器或默认重复调用塞进生产。
5. **分开机制正确与模型正确。** 305 项检查、重放通过和若干真实成功都不能证明全局无答案判定。原循环 `completed` 只代表停止。

当前没有实现 Skill 正文全文索引、统一跨来源搜索、语义召回、通用无进展检测或答案语义裁判。后续若专门处理负面结论，应先定义任务需要的证据覆盖合同，再决定由现有 owner 提供什么可验证信息；不要以中文关键词规则猜用户意图，也不要把模型自评变成批准事实。
