# DA-12：主方保留工作与助手互补交付

日期：2026-09-12。状态：六次真实配对完成，类别保持正确，互补实质分工未获证明，未采用。见[记录 038](../deal/038-complementary-work-contract.md)。

## 唯一改动与边界

DA-11 的独立输入让模型提交了决定，但两份 separable 提案仍是重复收集全部证据或先读后分析。原决定工具的 main_goal、child_goal、child_deliverable 没有 description。本轮只为这三个已有字段添加语义说明：main_goal 在 separable 时指主方保留的独立结果，不是总任务或仅最终整合；child_goal 指互补的独立只读结果；child_deliverable 指该子问题可核对的答案和证据，而非替所有工作收集片段。local 保持原含义。

沿用 DA-11 evidence-focused-system 的三份独立输入，每份原 schema / 补说明 schema 配对各一次，最多 6 次真实调用。其他字段约束、工具名字及总 description、system、目标、证据包、模型、temperature、输出上限完全不变。不给题型标签，不加入案例词，不新增字段或运行分支，不按关键词强制选模式。

这只是显式请求探针，复用原 Provider 和提案检查；返回工具不执行、不创建 Agent/Workspace，不接生产，不恢复 DA-9，不新增事实源或 Planner。原目标、证据及原 SQLite 身份回查继续成立。

## 预先约定的判读

程序记录 schema/字段关系合法性和 local/separable 标签；实现 Agent 离线核读，不冒充独立裁判或用户批准。三个场景预期仍为 separable/local/local，不能因调用合法就判通过。可拆提案需要同时满足：

1. 主方和助手各自有可回答的具体结果；主方有实际保留工作。
2. 两边可以从既有来源开始，不等待另一方未来结果；最终合并可以等待报告。
3. 不把全部材料取证同时交给两边，也不把助手仅当成替主方找齐所有资料的前置步骤。允许必要的共享背景和有明确目的的交叉核对，不要求路径完全不相交。
4. 合起来覆盖用户目标；助手只读、有可核对交付，不编造未见事实。

如果仍失败或分类倒退，如实保留，不改提示追跑。若改善，也只代表三个旧场景的提案结果；没有证明真实并行执行、报告交接、任务质量或一般收益，后续完整任务需另行冻结。
