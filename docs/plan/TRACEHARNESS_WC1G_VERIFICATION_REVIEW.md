# WC-1G：主方验证闭环

2026-09-13 冻结。本阶段承接 WC-1F 的实际失败，不改写旧成绩，不进入可写助手阶段。

## 根因和最小改动

已有提示要求不要虚报验证，但主方无工具调用的文字回答直接结束执行。固定 Verifier 能拒绝错误产物，却在主方结束以后才运行，无法让主方纠正报告。

在 Product 所拥有的 multi 策略中增加一次收尾检查点：execute 首次普通结束先继续到 review；由原 Session 中的 request view 和 assistant 事件推导阶段。review 可以调用原有工具，之后最终回答正常结束。取消、失败、预算仍优先，不追加预算、不无限自审。

review 请求附上当前主方 Turn 最近 8 个调用的事件定位、参数短预览、工具状态及已知退出码；显示省略数，缺失退出码保持 unknown，不读取隐藏结果，不把助手报告当实现测试。提示要求核对需求、实际实现、正向和边界检查，声明结果时引用真实调用。检查点不判断业务语义，不保证模型不撒谎，不新增事实账本，不修改 AgentLoop、单方、助手、固定验证或 Promotion 权限。

## 验证与停止

- 定向验证：未运行检查如实报告、成功与非零退出码区分、当前 Turn/主方隔离、请求重放、收尾取消，以及相邻 Product/预算/优化入口。
- 反向验证：移除 execute→review 的 Continue，真实 Product 测试必须因没有收尾请求而失败。
- 新题：coverage(windows, horizon)，两份规格分别定义输入边界和区间裁剪/合并。助手读取规格，主方实现与验证。不得把题目内容写入通用提示或规则。
- 一题一次，真实主方与助手使用现有连接直连；总上限 16 次、600 秒、主方 Turn 300 秒、单次连接 60 秒、无重试，无 baseline/额外语义裁判。连接失败或预算耗尽停止，不追加轮次。
- 运行前冻结源码、驱动、规格和固定检查；Docker 预检要求占位实现失败、参考实现通过。参考实现和固定检查不进入初始模型工作区。
- 分别报告交接、收尾检查是否发生、真实检查与最终声明是否一致、固定功能检查、资源收敛和请求重放。新题通过不能证明相对旧题提升或普遍可靠性。
- 不跑全量、L2–L4、Wheel；不提交、推送、发布，不提前开放可写助手。
