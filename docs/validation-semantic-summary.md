# D：模型语义摘要验证

2026-09-09；范围为 ADR-0057。调用使用用户授权的当前模型连接，凭据仅经现有配置加载器进入内存；没有修改用户的 Profile、工作区或 Session。真实执行只发生在独立测试目录。

## 真实案例与结果

测试夹具为离线档案整理器：随机输出文件名、禁止联网和覆盖原始数据、只运行一次准备好的本地检查。两个检查脚本分别返回 `CHECK_PASSED/exit_code=0` 与 `CHECK_FAILED/exit_code=7`，输出随机记录标识；这些脚本仅证明夹具结果，不是项目完整验收。

每组 8 轮：确认约束 → 真实 shell 检查 → 100 条废弃候选备忘 → 最近轮复核 → 开启摘要后回答目标/约束/检查状态 → 重启读回记录标识 → 查找摘要省略的随机第 071 条候选 → 换题计算。模型不知道随机答案，最后的候选查证必须真正调用 `request_history_page`；不能靠模板猜中。

最终 run-03 两组 **16/16 回合**满足固定答案断言，**22 次实际模型调用**，两份 Session 各 155 个事件；最新源码重新检查不变量与全部请求快照均通过，事件未变。两个 shell 各执行一次，重启/查证没有重跑；2 次 History 原文页读取成功。原角色、工具结果、近期轮和当前问题保留。

人工核对实际 JSON：成功组仅把退出码、stdout/stderr 和执行次数作为验证进度；失败组保留失败结果、未知原因、是否允许重试和文件是否存在尚未证实。两组 decisions 均为空，助手解释单列 reported_progress，没有新增用户决定。模型对下一步仍可能提出超出授权的建议，但本次没有执行它们；语义正确性不能仅凭 JSON 校验担保。

## 探索运行如实保留

- run-01：3 次调用、9302 token；第三个用户输入超出测试夹具显式 query 上限，在 Provider 前失败。调整夹具上限为 16000 字节并随机化候选名称，未放宽生产默认。
- run-02：16 个回合、22 次调用、108457 token。断言通过，但人工发现摘要把助手的“无需继续修改”当作已作决定；收紧通用归属说明后完整重跑 run-03。run-02 是旧提示词的探索证据，不冒充最终源码重建结果。
- 三次总计 **47 次实际模型调用、225518 token**。没有隐藏探索成本，也没有把传输/格式失败当成功。
